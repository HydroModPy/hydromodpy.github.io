hmp run#

Uses hmp.check(), hmp.run().

$ hmp run [-h] [--format {table,json,csv}] [--profile [HTML_PATH]] [--verbosity {quiet,normal,verbose,debug} | -q | -v | --debug] [-w WORKSPACE] [--base DIR] [--resume [REF]] [--from STEP] [--until STEP] [--dry-run] [--frozen] [--force] [--only WHAT] [--site SITE] [--parallel N] [--fresh] [--case NAME] [--no-display] [--overlay OVERLAY] [--set PATH=VALUE] [--credentials PATH] [--allow-host HOST] [--max-download-bytes N] [config]

Run a workflow from a TOML config or a JSON run request

ArgumentWhat it does
configPath to a TOML config or to a JSON run request (omit when using --resume REF)
--base DIRThe folder the relative paths of the configuration are read from, and the project the run is written in. It wins over -w and over the project root above the file.
--resume [REF]Continue an interrupted case in place, from the journal of its directory. With a TOML config, REF is the case name to continue (bare: the case the file names), or <chain>_w<N> for one window of a chain (island_w3); without a config, REF is the case name and the run replays its own runs/<name>/config.toml. A calibration takes a bare --resume and reopens the latest session of its case. On a [sites] project, bare --resume starts only the cases with an unfinished attempt.
--from STEPStart from this pipeline step, by its name.
--until STEPStop after this pipeline step, by its name. On a [sites] project, --until data stops after the prepare phase.
--dry-runPrint the resolved workflow plan without executing it.
--frozenOn a project TOML, reject any fresh download: every file must already be in the data cache and match hydromodpy.lock. The config.toml of a sealed run is refused: hmp replay plays a run again.
--forceGo past what the command refuses because of what is there: recompute when a completed run with an identical resolved config and the same name already exists, and claim a stale case whose process cannot be proven dead. Without it an identical run is not recomputed: the command stops and names it. A calibration searches again instead of giving back its completed session. Not for an overview. On a [sites] project it also lifts the budget ceilings (parallel, prepare_parallel, calibrations, cores), takes over the lease of a launcher still alive and plans over a running case.
--only WHAT[sites] project: start only these cases, named by status (failed, stale, partial, aborted, planned, completed) or by case id (shell patterns allowed). Repeatable, or comma separated.
--site SITE[sites] project: start only the cases of this site.
--parallel N[sites] project: solves side by side, a calibration counting its own [calibration] parallel. Defaults to [sites.run] parallel.
--freshStart the case over: everything the previous attempt left in runs/<case>/ is filed under attempts/<k>/ first. Without it a retry resumes in place.
--case NAMEName of the run. Defaults to [simulation] name, else the stem of the TOML. A run launched with --set or --overlay keeps that name; use --case to name the variant.
--no-displaySkip auto-rendering of the figures listed in [display].figures.
--overlay OVERLAYTOML overlay applied after base_config inheritance. Repeatable. How overlays merge into the file
--set PATH=VALUEDotted TOML override applied after overlays, e.g. flow.param.K.field.value=2e-5. The grammar of a key path and a value

Also takes the shared options --format --profile --verbosity --quiet --verbose --debug --workspace --credentials --allow-host --max-download-bytes.

Examples

$ hmp run run.toml
$ hmp run run.toml --dry-run
$ hmp run run.toml --set flow.param.K.field.value=2e-5
$ hmp run run.toml --overlay daily.toml --case baseline_daily
$ hmp run run.toml --from setup_process --until run_solver
$ hmp run --resume baseline_monthly
$ hmp run run.toml --fresh
$ hmp run request.json --base /project

Exit codes it sets itself: 2 10 14 21 23 130. An exception it does not catch ends with the code of its class. All exit codes.
