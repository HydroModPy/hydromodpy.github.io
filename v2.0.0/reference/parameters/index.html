TOML parameters#

Every section of the configuration file, generated from the models. Each page reads like the file you write: one block per table, the keys you must write first, optional keys commented with their default, developer and expert keys behind a switch, one tab per shape when a table has several. Click a line for its card.

Two commands go from a block to a verdict:

hmp config template --modules flow > flow.toml   # the keys of one section
hmp check my_run.toml                     # validate a file

  • # commented line optional: the value shown is the default
  • ‹form› no default: the accepted form of the value

Sections#

Required sections first, then the others in the order of the code.

[workspace]Where the shared input data of the project are read and cached.3 user · 1 dev/expert required dev
[geographic]Configuration block for geographic and watershed delineation parameters.43 user · 10 dev/expert required
[edition]The set of defaults the file is read with.1 user · 0 dev/expert
[workflow]Workflow configuration: workflow.mode ('simulation', 'calibration' or 'overview'), the console verbosity and the profiler.2 user · 1 dev/expert
[site]The catchment this project models: its name, label, gauge and registry URI.4 user · 0 dev/expert
[sites]The catchments of a campaign and the recipes run on each of them: the plan is sites x recipes, one case <site>-<recipe> per pair.23 user · 3 dev/expert
[metrics]Where and when a run is scored after it ends: the station (default [site] gauge) and the window.3 user · 0 dev/expert
[publication]Licence, creators and attribution written into every copy hmp publish makes of a result. hmp publish --public refuses a project without a licence.3 user · 0 dev/expert
[domain]Domain configuration: the depth of the aquifer ([domain.depth_model]), its layering ([domain.layers], read by every solver) and the spatial-support mode used for heterogeneous parameter mapping (none, geology, or zones).25 user · 4 dev/expert
[data]Data-managers configuration.303 user · 136 dev/expert
[flow]Flow process configuration with declared parameter ids in [flow].param_list and payloads validated from [flow.param.<id>] TOML sections.364 user · 105 dev/expert
[transport]Transport process configuration, with one parameter table per transport, written [transport.<name>].28 user · 22 dev/expert
[simulation]Optional simulation orchestration block loaded from [simulation] and [[simulation.process]].25 user · 4 dev/expert
[solver]Global solver block loaded from [solver]: the flow solver in solver.backend, the settings of each flow solver under its name, and the backend-agnostic preprocessing switches (solver.sink_fill, solver.drain_band_depth_m).14 user · 89 dev/expert
[display]The figures a run draws, loaded from the [display] section.109 user · 1 dev/expert
[[export]]The exports written at the end of a run, one [[export]] block per request, in the order of the file.10 user · 1 dev/expert
[observation]Observation points declared in [observation] and sampled while the run still holds its fields.7 user · 0 dev/expert
[overview]Optional overview report settings loaded from the [overview] section.14 user · 0 dev/expert
[mesh]Optional mesh settings loaded from the [mesh] section: which engine meshes the model ('regular', 'triangle', 'voronoi' or 'catchment') and how fine.25 user · 9 dev/expert
[calibration]Optional calibration settings loaded from the [calibration] section.116 user · 5 dev/expert
[spinup]Optional cyclic spin-up settings loaded from the [spinup] section.5 user · 0 dev/expert
