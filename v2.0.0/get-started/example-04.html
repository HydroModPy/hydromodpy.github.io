Example 04#

Example 04 models the Nançon catchment (Ille-et-Vilaine) with MODFLOW 6, from 2000 to 2002 in monthly stress periods. As the recharge swings between wet winters and dry summers, the cells where the water table reaches the ground spread out and draw back. The example is two files. project.toml says the model, its figures and its exports, and hmp run plays it in about a minute and a half. py1_run_and_plot.py plays the same file one step at a time from Python, looks at what each step built, and tries three values of Sy.

Get the example#

hmp workspace init ~/hydromodpy
hmp example add 04 -w ~/hydromodpy
cd ~/hydromodpy/projects/04_streamflow_intermittence_in_transient

hmp example add downloads the files of the example, about 92 MiB, most of it a regional DEM. Files are cached by content, so a second workspace costs nothing. hmp example list shows the examples your version ships and hmp example show 04 lists the files one by one.

The model file#

The file opens with the catchment. [site] names it and its gauge, NANCON. Every series below reads that station: the discharge, and the SIM2 recharge and runoff averaged over the catchment. [metrics] sets the window the discharge is scored on, 2001 and 2002, so the year 2000 is spin-up.

Run the file#

hmp run project.toml

import hydromodpy as hmp

run = hmp.run("project.toml").open()
print(run.name)

A relative path is read from the folder you are in. hmp.run returns the Run, whose reference page lists what it reads.

The run writes its figures to runs/nancon_intermittence_mf6/figures/ and its exports to runs/nancon_intermittence_mf6/exports/. The last line gives the name of the run and the NSE of the discharge at the gauge, about 0.97.

Run an unchanged file a second time and nothing is computed. The command says which run is already there, and hmp run --force computes it again. Edit the file, even one value, and the second run is a new one, runs/nancon_intermittence_mf6_v2/, then _v3. A name is never given out again: hmp ls lists the versions, hmp diff compares them, and a deleted run goes to the project trash.

What can go wrong#

Message

Cause

What to do

Outlet moved 130 m (limit 150 m) onto the flow network, a WARNING line of every run

The coordinate of the file does not fall on a stream cell of the DEM, so the outlet moves to the cell with the largest flow accumulation in a window of geographic.catchment.snap_dist, here 150 m.

Nothing, here. A move close to the limit means the coordinate is far from the stream, so check it.

Flow solver '<solver>' failed for run, with a percent discrepancy and did not converge from the listing file

A very small Sy lets the water table move by metres in a month, and MODFLOW 6 does not converge in one time step. The script meets it with Sy = 0.001.

Cut each month in several time steps with simulation.time.substeps_per_period, as the script does with 4.

The script, step by step#

py1_run_and_plot.py sits next to the file. It finds the project from its own location, so it runs from any folder, and it can be stepped through cell by cell (# %%) in Spyder or VS Code. It plays the model in a lab, which builds the model in memory one step at a time and writes no run until it is asked to.

After load_data, the forcing of the station is in memory, one value per month. The script draws it.


state = lab.advance("load_data")
print(state.geographic)
print(state.data)

# The recharge and the runoff over the catchment, one value per month in mm/day. The model takes
# the recharge, and the runoff is added to the drain flow to give the discharge.
forcing = pd.DataFrame(
    {
        name: getattr(state.data, name).points[0].data.set_index("datetime")["value"]
        for name in ("recharge", "runoff")
    }
)
print(forcing.describe().round(2).to_string())
fig, ax = plt.subplots(figsize=(7, 3))
ax.plot(forcing.index, forcing["recharge"], color="dodgerblue", lw=2, label="recharge")
ax.plot(forcing.index, forcing["runoff"], color="navy", lw=2, label="runoff")
ax.set_ylabel("mm/day")
ax.legend()
fig.savefig(FIGURES / "recharge_and_runoff.png", dpi=150, bbox_inches="tight")

A run stopped at prepare_solver already stores the ground of every cell, so it draws the mesh on the relief before anything is solved.


# A run stopped at `prepare_solver` stores the ground of every cell, so it draws the mesh.
state = lab.advance("prepare_solver")
print(state.model)
before = lab.run(until_step="prepare_solver")
print(
    before.figure(
        "topography",
        overlays=["mesh", "outline", "network", "outlet"],
        save=FIGURES / "mesh_on_relief.png",
    )
)

Then Sy takes three values, and each one is kept as a run with the figures and the files of project.toml. The value of the file gives the run of project.toml, so it is not solved twice. With Sy = 0.001 the water table moves by metres in a month, and MODFLOW 6 needs four time steps per month to converge.


# Sy sets how much water the aquifer stores for a metre of water table. Each run writes the
# figures and the files of project.toml. Sy = 0.05 is the value of the file, so its run is
# the run of project.toml.
SY = {"small": 0.001, "file": 0.05, "large": 0.3}
runs = {}
for label, sy in SY.items():
    # With Sy = 0.001 the water table moves by metres in a month, and MODFLOW 6 needs four
    # time steps per month to converge. That run takes about three minutes.
    steps = 4 if label == "small" else 1
    lab.set({"Sy": sy, "simulation.time.substeps_per_period": steps})
    runs[label] = lab.run(None if label == "file" else f"nancon_sy_{label}")
lab.close()

Each run gives the months when the catchment seeps the least and the most, and run.figure draws the seepage cells and the water table of these two months from the sealed run, so nothing is solved again. A small Sy lets the water table follow each month: the network swells in winter and nearly dries in summer. A large Sy smooths the year.


# The fields are stored by month. Each month is named by its first day, and the figures take
# the middle of the month. Only the cells of the catchment are counted.
rows = []
for label, run in runs.items():
    months = run.periods.edges[:-1]
    seeps = run.read("seepage_mask").to_numpy()[:, run.catchment_mask.ravel()] > 0
    share = pd.Series(seeps.mean(axis=1) * 100, index=months)
    scores = run.metrics.set_index("metric")["value"]
    rows.append(
        {
            "Sy": SY[label],
            "least (%)": share.min(),
            "in": share.idxmin().strftime("%Y-%m"),
            "most (%)": share.max(),
            "in ": share.idxmax().strftime("%Y-%m"),
            "NSE": scores["nse"],
            "NSE log": scores["nse_log"],
        }
    )
    for word, month in (("least", share.idxmin()), ("most", share.idxmax())):
        middle = (month + pd.Timedelta(days=14)).strftime("%Y-%m-%d")
        print(
            run.figure(
                "seepage_mask",
                time=middle,
                overlays=["outline"],
                save=FIGURES / f"seepage_sy_{label}_{word}.png",
            )
        )
        print(
            run.figure(
                "watertable_elevation",
                type="section",
                time=middle,
                line=SECTION,
                save=FIGURES / f"section_sy_{label}_{word}.png",
            )
        )
# A small Sy lets the water table follow each month, so the network swells in winter and
# nearly dries in summer. A large Sy smooths the year.
print(pd.DataFrame(rows).set_index("Sy").round(2).to_string())

The script takes about six minutes, most of it the run with the small Sy. Its figures land in summary/figures/, beside the runs.
