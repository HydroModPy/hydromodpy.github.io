Coming from version 1#

Version 1 was a set of Python scripts. You built a Watershed object, called add_* and update_* methods on it, and ran MODFLOW with preprocessing_modflow and processing_modflow. Version 2 puts the same choices in a TOML file. You run it with hmp run, and every run is stored in a folder you can read without HydroModPy.

The v1 scripts stay on the tag v1.0.0, and the branch v1.0 is frozen. Nothing forces you to move a finished study. For a new one, start from A first run.

What changes#

  • Every setting is a key in a TOML file. There are no setter calls.

  • A project is a folder with a project.toml. A run file names it with base_config and states only what it changes. A loop over a parameter becomes several run files, or a calibration.

  • Results go to runs/<name>/ as Zarr, Parquet and JSON. There is no pickle file to reload.

  • Units are written with the value, as in "30 m" or unit = "m/s". Version 1 expected meters and days. Version 2 stores SI units, so a v1 hk in m/day must be divided by 86400 or written with its unit.

  • Data come from a [data] table, either from a provider or from your own file.

Every command takes -w <workspace>, and prints JSON with --format json. The full list is in Command line.

Moving a study#

  1. Run hmp workspace init and put your input files in ~/hydromodpy/data/.

  2. Write a project.toml with the site, the catchment, the depth and the data. Example 04 shows a whole file, section by section.

  3. Run it with a steady regime first. Check the figures, then add the dates and the forcings.

  4. Compare with your v1 results through hmp diff or a notebook.

Results are not bit for bit equal to version 1. The recharge, the drains and the meshing were rewritten, and each change is in the changelog.
