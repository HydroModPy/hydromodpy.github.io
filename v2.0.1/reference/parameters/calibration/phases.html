[[calibration.phases]]#

One stage of a calibration that runs in several.

  • calibration.phases [[array of tables]] · optional · 25 user keys

Repeat the table: one [[calibration.phases]] block per item.

Connections found in the code (1)
  • The code says calibration.parameters: [calibration.parameters....] points at ..., which is a stage boundary and not a dimension a search may move: it says which model the stage runs, not a property of that model. Declare it in a phase's [calibration.phases.overrides] instead, which is how a two-stage method makes one stage steady and the next transient.

More

Unset, the phase runs the method [calibration] writes; failing that it follows from what the phase scores: 'bisection' when the phase moves one parameter in log space and every one of its blocks is signed (distance_gap), since the answer is then a zero to find; 'scipy_nelder_mead' otherwise, a cost to minimise. hmp calibrate --list-phases prints the method and where it comes from. Write it to depart from that choice, and whenever method_options are given and [calibration] writes no method. Built-ins: 'grid' (regular sweep, sized by method_options.points_per_dim), 'lhs' (stratified Latin hypercube, sized by method_options.n_samples), 'random_search', 'bisection' (root of a signed criterion on one parameter, the stream-network stage), 'optuna' (TPE), 'cma_es', 'scipy_de', 'scipy_nelder_mead' and 'gp_mapping'. An unknown name is refused when the file is read, with the list installed here.

# objective = ‹"rmse" | "nse" | "kge" | "mae" | "nse_log" | "nse_delta" | "nse_seasonal" | "reservoir" | "distance_gap" | "distance_mean" | "bfi_error"›Metric scoring this phase's single simulated series, when the phase does not use objective blocks. experimental
Path
calibration.phases.objective
More

Same vocabulary as a block's 'metric'.

Values
  • "rmse" : Root-mean-square error, in the observed unit; penalizes large misfits most.
  • "nse" : Nash-Sutcliffe efficiency against the observed mean; the standard choice for a level or discharge series.
  • "kge" : Kling-Gupta efficiency, 2009 form (bias as the ratio of sums, variability as the ratio of standard deviations); separates correlation, variability and bias when NSE alone is ambiguous.
  • "mae" : Mean absolute error, in the observed unit; less sensitive to outliers than RMSE.
  • "nse_log" : NSE on log-transformed series; weights low flows as heavily as peaks, good for recessions.
  • "nse_delta" : NSE on the increments of the series rather than its level; a level is an integral and can hide flux errors that compensate, which only its increments show.
  • "nse_seasonal" : NSE against the seasonal cycle rather than the overall mean; asks whether the model beats climatology.
  • "reservoir" : Half nse_seasonal plus half nse_delta, built for an impounded level: a plain NSE there is beaten by the seasonal cycle, and the increments are what carry the flux errors.
  • "distance_gap" : Balances the simulated stream network against the mapped one; zero marks the crossing.
  • "distance_mean" : Mean spatial offset between simulated and mapped streams; a diagnostic, not a substitute for distance_gap.
  • "bfi_error" : Distance between the simulated and observed baseflow indices (Wallingford, daily discharge only); asks whether the stream is fed by its aquifer in the right share. Blind to volume and timing, so it goes beside a fit, never alone.
Accepted
"rmse" | "nse" | "kge" | "mae" | "nse_log" | "nse_delta" | "nse_seasonal" | "reservoir" | "distance_gap" | "distance_mean" | "bfi_error"

calibration.phases.regime
More

'steady' is one period over steady_window, by default the extent of [simulation.time]. 'transient' is the project's own time grid. 'soil' runs no solver: it sets ru to the capacity that closes recharge plus runoff against the gauge, on the soil reservoir alone, and holds it for the phases after it. Unset, the phase runs the model as the project and its overrides declare it.

Values
  • "steady" : One period over steady_window, so the recharge over it averages to its mean. A steady solve carries no storage.
  • "transient" : The project's time grid, with only the regime restated.
  • "soil" : No solver: ru closes the water budget of the soil against the gauge, then the next phases calibrate K and Sy with it fixed.

More

The values it passes on enter this one fixed, except those this phase lists and moves again. When that phase freezes its values and its search stops on its budget before a rule of its own, this phase is refused rather than run on the values of the file.

Accepted
string
# freeze_on_success = truePass the values this phase found to the phases after it. experimental
Path
calibration.phases.freeze_on_success
More

A later phase holds them fixed, unless it lists the parameter: it then moves it again, starting from the passed value when its method accepts a start point. When two phases pass on the same parameter, the later one wins. Success means the search met its own rule or solved every point of its plan, not that its validity indicator is good. A search with no rule of its own (random_search, cma_es) that spends its budget also passes on its best trial, and the phase says it froze the best of a budget-only search. One with a rule that its budget stops first passes nothing on.

Accepted
true | false

# method = ‹"cost_profile" | "multistart" | "linearized"›How this phase's interval is obtained: 'cost_profile', 'multistart' or 'linearized', read as in [calibration.uncertainty] method. experimental
Path
calibration.phases.uncertainty.method
See
calibration.uncertainty
Values
  • "cost_profile" : Reads the range of sampled values whose cost stayed within cost_margin of the best, off the trace of the search. No extra model run.
  • "multistart" : Repeats the whole search restarts times from different starting points and reports the spread of the optima. It can see a second basin.
  • "linearized" : Linearizes the model about the optimum: one extra run per parameter gives a first-order covariance, and with it which parameters trade off.

calibration.phases.uncertainty.method method not set cost_profile multistart linearized cost_profile Reads the range of sampled values whose cost stayed within cost_margin of the best, off the trace of the search. No extra model run. multistart Repeats the whole search restarts times from different starting points and reports the spread of the optima. It can see a second basin. linearized Linearizes the model about the optimum: one extra run per parameter gives a first-order covariance, and with it which parameters trade off. How this phase’s interval is obtained: ‘cost_profile’, ‘multistart’ or ‘linearized’, read as in [calibration.uncertainty] method. calibration.phases.uncertainty.restarts restarts not set - How many times method=’multistart’ repeats this phase’s search. calibration.phases.uncertainty.perturbation perturbation not set - Relative step of method=’linearized’ for this phase, as a fraction of each calibrated value. calibration.phases.uncertainty.cost_margin cost_margin not set % or m Width of this phase’s interval, with its unit: ‘5%’ is a share of the best cost, ‘75 m’ a length, for a phase scored only by network distances. Unset here and in [calibration.uncertainty], one mesh cell for a phase scored only by network distances, five per cent of the best cost otherwise.
