class Catalog(project_root, *, read_config=None, render=None)[source]#

Read-only view of a project index.

Parameters:

  • project_root (Path | str) – The project directory, the one holding runs/ and .hmp/.

  • read_config (Callable[[Mapping[str, Any]], BaseModel] | None) – The function that validates a sealed configuration snapshot, handed to every run this catalog builds. Without one, run.hydromodpy_config is refused. A catalog opened by hmp.open or by a Project carries it.

  • render (Renderer | None) – The function that draws a figure or writes a report for a run, a session or a set of runs, handed on like read_config to every object this catalog builds. Without one, figure is refused. It is hydromodpy.project.show.render() for a catalog opened by a Project.

Raises:

  • FileNotFoundError – If the directory is not a project.

  • hydromodpy.core.exceptions.WriteConflictError – If the index had to be built and another process keeps its lock.

  • hydromodpy.core.exceptions.SchemaVersionMismatchError – If the index was written under another schema version.

  • hydromodpy.core.exceptions.CatalogUnreadableError – If the index file exists but DuckDB cannot open it.

Examples

>>> import hydromodpy as hmp
>>> catalog = hmp.open("~/hmp_workspace/projects/nancon")
>>> catalog.latest().summary()

See also

hydromodpy.results.run.view.Run

Per-simulation view returned by catalog queries.

hydromodpy.results.run.group.RunSet

Multi-run view returned by cohort queries.

Catalog.best(project, metric='nse', *, site=None, mixed_windows=False)[source]#

Return the completed run with the best value of metric under its rule.

Best follows the direction of the metric: the highest nse, the lowest rmse, the pbias closest to zero. A metric with no declared direction raises UnrankedMetricError. Runs scored under different rules (station, variable, window or rule version) are not comparable: they raise MixedWindowsError unless mixed_windows is true.

Catalog.diff(ref_a, ref_b, *, project=None)[source]#

Compare two runs’ parameters and metrics.

Returns {"a", "b", "params", "metrics"}. params maps each differing (name, zone) to (value_a, value_b). metrics maps each differing (metric, station, variable) to one entry per run, {"value", "window_start", "window_end", "n"}: the score and the window and samples it was computed on. An entry is None when the run holds no such score.

Catalog.find(*, mixed_windows=False, **filters)[source]#

Return the runs that match every filter, newest first.

Parameters:

  • **filters –

    Each keyword narrows the set:

    • project, site, site_fingerprint, case_id, recipe, rel_dir, name, name_stem, solution_key, request_id, crs_wkt (or crs): exact value of that run column.

    • solver, solver_category, status, flow_regime, mesh_topology: their code, for example solver="modflow6" or status="completed".

    • mesh_engine: the engine that built the mesh, for example "voronoi", read from the stored configuration.

    • tags: one tag the run carries.

    • <metric>_gt, <metric>_gte, <metric>_lt, <metric>_lte: bound on a metric scored under the run’s metric rule, for example nse_gt=0.7. A bound reads every score against one number, so the runs it is applied to must share one rule (station, variable, window, rule version): runs that carry the metric under different rules raise MixedWindowsError.

  • mixed_windows (bool) – Apply the bounds although the runs were scored under different rules. Refused by default.

Returns:

RunSet – The matching runs. It is empty when nothing matches.

Raises:

  • ValueError – If a keyword is none of the above, or names a metric the catalog does not know (a retired spelling is refused with the name to write). The message lists them.

  • MixedWindowsError – If a <metric>_gt style bound meets runs scored under different rules and mixed_windows is false.

Return type:

RunSet

Examples

>>> good = cat.find(
...     site="basin_a", status="completed", nse_gt=0.7
... )
>>> good.best("nse")

Return up to n completed runs ranked on metric under their metric rule.

Without ascending the runs come best first (best_first=True) or worst first, following the direction of the metric. ascending orders on the raw value instead, for a metric with no direction. Catalog.resolve(ref, *, project=None, site=None, mixed_windows=False)[source]#

Resolve a user reference to a simulation UUID.

Accepted forms, tried in order:

  1. @-selectors: @last, @last~N (N-th newest completed), @best:METRIC / @worst:METRIC (the metric scored under the run’s metric rule; add @STATION to read another station), @running. site narrows a selector to the runs of one site. Best follows the direction of the metric: highest nse, lowest rmse, pbias closest to zero (see METRIC_SENSE). @best and @worst rank scores, so the runs they rank must share one rule (station, variable, window, rule version; with @STATION, all but the station): otherwise they raise MixedWindowsError, unless mixed_windows is true.

  2. A relative directory: runs/<name>, sessions/<name>, sessions/<name>/trials/<nnnn>.

  3. Full UUID (36 chars with dashes).

  4. UUID prefix of >= 4 hex characters, or the run directory name <name> (runs/<name>). A hex word that is both a prefix and a name of two different runs raises AmbiguousReferenceError.

Raises SimulationNotFoundError when nothing matches, with the closest directory names suggested.

Catalog.query_field(sim_id, variable, timestep, layer=None)[source]#

Read one stored period of a field as an array.

  • variable (str) – Field name, for example "head".

numpy.ndarray – The values of that period, one per cell (and per layer).

Raises:

ndarray

>>> heads = cat.query_field(

Series
