The mesh#

The solver does not see the DEM. It sees cells, and one top elevation, one bottom elevation and one centre for each of them. This page gives the rules that turn the DEM into those cells: how the cells are laid out, how the top of a cell is read from the DEM, how many cells a given size costs, and which checks the code runs on the result.

Note

Scope. The cell layout below is the one of MODFLOW 6, which reads every grid as a DISV grid. MODFLOW-NWT builds a structured grid only and ignores a runtime mesh. Boussinesq uses the triangles of the Gmsh mesh as its cells, so the Voronoi dual of 3. The Voronoi dual does not apply to it, and it ignores the top sampling of 5. The top of a cell. What the solver does with the cells is on The solvers of the aquifer. The extra terms XT3D adds on a non-orthogonal mesh are on XT3D on irregular meshes. To set up a mesh, see [mesh_catchment].

The chain in one list#

The code builds the cells in this order. Each step is a section below.

  1. Two surfaces: the top from the DEM \(Z\) and the bottom from the depth model.

  2. A planar support, from one of two sources: the pixels of the DEM (a structured grid, 1. A structured grid), or a Gmsh triangulation built at run time (2. A runtime mesh from Gmsh), which MODFLOW 6 turns into its Voronoi dual by default (3. The Voronoi dual).

  3. One top elevation per cell (5. The top of a cell) and one bottom elevation per cell.

  4. A check of the thickness (8. The checks the code applies), then the layers (6. Thickness and layers).

  5. The export to MODFLOW 6 as a DISV grid. The cells that have no valid top or bottom are written inactive.

Example 04 uses the first source: its files declare neither a [mesh_catchment] section nor a [modflow6.sgrid] section, so every cell is one DEM pixel. The header of step1_minimal.toml counts 21406 cells of 75 m for this domain.

1. A structured grid#

With modflow6.sgrid.planar.mode at its default, the cells are the pixels of the top raster, with the same size and the same extent. A cell \((i,j)\) takes the value of pixel \((i,j)\), with no interpolation:

\[ z_{\mathrm{top},ij} = Z_{ij}, \qquad N_S = n_{\mathrm{row}}\, n_{\mathrm{col}}, \qquad a_{ij} = \Delta_x \Delta_y . \]

A pixel that is nodata makes the cell inactive. The cell still exists in the grid, so \(N_S\) counts the active and the inactive cells.

With modflow6.sgrid.planar.mode set to resample the grid to a shape, top and bottom are resampled to \(n_{\mathrm{row}} \times n_{\mathrm{col}}\) cells over the same extent, with the rule of modflow6.sgrid.planar.resampling (project_surfaces_to_planar_grid). If a cell then covers at least two DEM pixels, the top of the cell is the zonal statistic of 5. The top of a cell instead of the resampled value (_cells_cover_pixels, _zonal_structured_top). A grid whose cells are the pixels is never touched by the zonal top.

MODFLOW 6 reads this grid as a DISV grid. MODFLOW-NWT reads it as a DIS grid.

2. A runtime mesh from Gmsh#

A [mesh_catchment] section makes the run build a triangulation of \(\Omega\) with Gmsh before the solver is prepared (run_mesh_phase). The project refuses a file that has both a [mesh_catchment] and a [mesh_input] section (Embedded [mesh_catchment] and external [mesh_input] are mutually): they are two sources for the same mesh. A mesh that already exists is declared with mesh_input.mesh_path or mesh_input.bundle_dir instead, and goes through the steps below like a mesh the run built.

The triangle sizes come from a size field, in the sense of the Gmsh manual ([Geuzaine and Remacle, 2009], reference manual): a Distance field to some curves, a Threshold field on it, and the minimum of all fields. Around the interface curves (rivers, geology interfaces, the catchment boundary), when mesh_catchment.zone_meshing.refine_interfaces is on, the code sets the lower distance of the Threshold to zero. With \(\xi\) the distance to the nearest interface, the wanted size is linear between the two limits:

(21)#\[ \ell_0(\xi) = \ell_s + (\ell_g - \ell_s)\,\min\!\left(1, \frac{\xi}{\xi_s}\right). \]

When the refinement policy is on, there is one such field per family of curves, with its own \(\ell_s\) and \(\xi_s\) (apply_family_refinement_fields). The size actually used is bounded by Gmsh options the code sets from the three keys of the section (apply_mesh_options):

(22)#\[\begin{split} \ell(\mathbf{x}) = \min\!\bigl(\ell_{\max}',\ \max(\ell_{\min}',\ \ell_0(\mathbf{x}))\bigr), \qquad \ell_{\min}' = \begin{cases}\ell_{\min} & \text{if set,}\\ \ell_g & \text{otherwise,}\end{cases} \qquad \ell_{\max}' = \begin{cases}\ell_{\max} & \text{if set,}\\ \ell_g & \text{otherwise.}\end{cases} \end{split}\]

The fields of the lakes, of the refinement zones and of the coarsening outside the catchment join the interface fields (set_background_mesh_from_fields). The upper bound is raised to the largest size of such a regional field when the section declares one (compute_effective_max_size). The lower bound has a consequence that the keys do not announce: with no mesh_catchment.zone_meshing.min_size, \(\ell_{\min}' = \ell_g\), and every size below \(\ell_g\) is raised back to \(\ell_g\). An interface_size\ below the background size then changes nothing (Limits).

The 2D algorithm is the one named by mesh_catchment.zone_meshing.algorithm. The code knows four names and maps them to the Gmsh codes. Gmsh does not give the same triangulation twice for the same input. mesh_catchment.cache keeps the first one and reuses it while the inputs that shape the mesh are unchanged.

3. The Voronoi dual#

MODFLOW 6 does not take the triangles as cells by default. With modflow6.sgrid.grid_dual at its default, the code takes the vertices of the triangulation as seeds \(\mathbf{s}_i\) and builds the Voronoi (PEBI) cell of each seed, that is the set of points closer to it than to any other seed, clipped to the outline \(\Omega\) of the triangulation.

The cell centre written to the DISV file is the seed itself. Three rules complete the construction:

  • A seed whose cell falls entirely outside \(\Omega\) is dropped.

  • When the clip splits a cell, the piece that contains the seed is kept.

  • If no piece contains the seed, the largest piece is kept and its representative point becomes the centre.

The outline \(\Omega\) is rebuilt from the edges that belong to exactly one triangle. The coordinates of the vertices are rounded to 1 mm so that the corners shared by two cells are one vertex, which assumes a projected CRS in metres.

Three consequences follow.

The number of cells. The dual has one cell per seed, so \(N_V = n_v\), the number of vertices. By Euler’s formula a triangulation of a region without holes has \(N_T = 2 n_v - n_b - 2\) triangles, \(n_b\) being the vertices on its outline, so \(N_V \approx N_T / 2\) when \(n_b\) is small against \(n_v\).

The faces. The face between two cells is the perpendicular bisector of the segment between their seeds. The faces are not the edges of the triangulation. A river that was a chain of triangle edges runs through the middle of a chain of Voronoi cells: it is no longer the boundary of any cell.

The orthogonality. The line between the two centres is perpendicular to the face, so \(\varphi_{nm} = 0\) on every connection whose two cells kept their seed as centre. 4. Flow between two cells, and the angle says why this matters. As a check, 36 seeds on a \(6 \times 6\) lattice (the 16 inner ones moved at random, \(n_b = 20\)) give 50 triangles, and voronoi_dual_of_mesh returns 36 cells with \(0^\circ\) on every connection.

The features. Wells and boundaries are placed on the dual cells, not on the triangles. A well goes in the cell that holds its point. A side boundary takes the cells whose seed lies on that side, so the head is held on the boundary and not in a clipped inner cell that only touches it; a corner cell belongs to both sides. A side with no seed on it falls back to the cells with a face on it, with a warning. The stream boundary takes the cells the river runs through.

With modflow6.sgrid.grid_dual set to "triangle", the triangles are the cells and the centre of a cell is the mean of its three vertices.

4. Flow between two cells, and the angle#

MODFLOW 6 writes the flow between two cells with the two-point finite-difference term \(G_{nm}\,(h_m - h_n)\) of (17) [Harbaugh, 2005, Langevin et al., 2017]. It is exact only when the conductivity is isotropic in the plane and the line between the centres is perpendicular to the shared face. HydroModPy measures the departure from that condition on every connection, as an angle. With \(\mathbf{d}_{nm}\) the vector between the two centres and \(\mathbf{n}_{nm}\) the unit normal of the shared edge:

(23)#\[ \varphi_{nm} = \arccos\!\left(\frac{\lvert \mathbf{d}_{nm} \cdot \mathbf{n}_{nm} \rvert} {\lVert \mathbf{d}_{nm} \rVert}\right). \]

Only an edge shared by exactly two cells counts as a connection. The summary the code keeps is the median, the 95th and 99th percentiles, the maximum and the share of connections above 30 degrees. What the angle does to the flux, and when the code turns on the XT3D option that corrects it, is on XT3D on irregular meshes.

Two triangles. Cut a \(2 \times 1\) rectangle along its diagonal. The shared edge goes from \((2,0)\) to \((0,1)\), with a normal along \((1,2)\). The centres are the vertex means, \((2/3, 1/3)\) and \((4/3, 2/3)\), so \(\mathbf{d} = (2/3, 1/3)\) and

\[ \cos\varphi = \frac{\lvert (2,1)\cdot(1,2) \rvert}{\sqrt5\,\sqrt5} = \frac{4}{5}, \qquad \varphi \approx 36.9^\circ . \]

The same corners, as seeds. The four corners of the rectangle, taken as seeds, give four cells of \(1 \times 0.5\) with four connections, all at \(0^\circ\). Both results were checked with connection_nonorthogonality_deg, and the four cells with voronoi_planar_mesh.

5. The top of a cell#

The top of a cell is one number, read from the DEM \(Z\). Two rules exist, set by modflow6.sgrid.top_sampling.mode. The bottom is always read by the first rule.

Centroid#

The DEM is sampled at the centre of the cell with a bilinear interpolation between the four pixel centres around it. The weights \(w_k\) are the bilinear ones, and a nodata pixel gets a weight of zero before the sum is normalised:

\[ \tilde z_c = \frac{\sum_{k=1}^{4} w_k\, Z_k\, \mathbf{1}[Z_k \text{ valid}]} {\sum_{k=1}^{4} w_k\, \mathbf{1}[Z_k \text{ valid}]} . \]

The result is undefined, and the cell inactive, when the centre is outside the raster or the four pixels are nodata. On an incised channel the centre of a cell often falls on a bank, not on the thalweg, and the cell is then too high.

Zonal#

The zonal rule reduces every pixel whose centre falls in the cell. A pixel belongs to the cell that contains its centre: for a mesh, the code burns each cell polygon into a raster of the DEM; for a structured grid, it computes the row and column by arithmetic. A pixel is channel when the stream raster of the delineation says so, with the mask widened by modflow6.sgrid.top_sampling.channel_buffer_px pixels. The raster is read only when modflow6.sgrid.top_sampling.channel_source asks for it. Without a stream raster, every pixel is a hillslope pixel.

With \(\operatorname{stat}\) the statistic named by modflow6.sgrid.top_sampling.channel_stat on the channel pixels, and by modflow6.sgrid.top_sampling.hillslope_stat on the others (mean, median, min, max, and the 10th and 25th percentiles):

(24)#\[\begin{split} z_{\mathrm{top},c} = \begin{cases} \operatorname{stat}_{\mathrm{ch}}\{Z_p : p \in P_c^{\mathrm{ch}}\} & P_c^{\mathrm{ch}} \neq \emptyset, \\[0.5ex] \operatorname{stat}_{\mathrm{hill}}\{Z_p : p \in P_c\} & P_c^{\mathrm{ch}} = \emptyset \text{ and } \lvert P_c \rvert \ge n_{\min}, \\[0.5ex] \tilde z_c & \text{otherwise.} \end{cases} \end{split}\]

A channel cell needs one channel pixel. A hillslope cell needs \(n_{\min}\) pixels, and a cell finer than the DEM falls back to the centroid value. Two corrections follow, in this order:

\[ \text{if } \lvert z_{\mathrm{top},c} - \tilde z_c \rvert > \varepsilon_z \text{ on a hillslope cell:}\quad z_{\mathrm{top},c} \leftarrow \tilde z_c, \]
\[ z_{\mathrm{top},c} \leftarrow \max\bigl(z_{\mathrm{top},c},\ z_{\mathrm{bot},c} + b_{\min}\bigr) \quad \text{on every active cell.} \]

The first one guards against a nodata edge: channel cells are exempt, since they are lowered on purpose. It is off when \(\varepsilon_z = 0\). The second one keeps a lowered top above the bottom. Only the top is zonal; the bottom keeps its centroid value, so a lowered top thins every layer of that column. The code logs, once per build, how many cells took a zonal value, how many are channel cells, and how far the tops were lowered.

The zonal rule falls back to the centroid value, with a message in the log, in three cases: a surface with no georeferencing (Zonal top sampling needs a georeferenced surface; using centroid sample.), a channel source with no stream raster (Zonal channel_source=%s but no stream raster found; the channel class is then off), and a structured grid whose cells cover fewer than two DEM pixels (Zonal top sampling skipped: a grid cell). In the code: zonal_top.

6. Thickness and layers#

The column of each cell is cut into layers by shares of its thickness, the same shares in every cell, set by modflow6.sgrid.vertical.genmtd_lay. The rule, (14), and its three strategies are on The solver grid and its layers.

Every layer shares the cells of the plan: the mesh is a vertical extrusion. A cell is inactive in every layer when its top or its bottom is nodata, not finite, or at or below the nodata value.

7. How many cells a size costs#

The cost of a run grows with the number of cells, so a structured grid and a mesh are compared at equal cell count. The ideal count below assumes cells of one uniform size over an area \(A_\Omega\).

For a structured grid of pixel side \(\Delta\):

\[ N_S = \frac{A_\Omega}{\Delta^2}. \]

For a triangulation of equilateral triangles of side \(\ell\), the triangle area is \(\frac{\sqrt3}{4}\ell^2\). The Voronoi cells are hexagons, whose area is \(\frac{\sqrt3}{2}\ell^2\) when two neighbouring seeds are \(\ell\) apart:

(25)#\[ N_T = \frac{4}{\sqrt3}\,\frac{A_\Omega}{\ell^2} \approx 2.31\,\frac{A_\Omega}{\ell^2}, \qquad N_V = \frac{2}{\sqrt3}\,\frac{A_\Omega}{\ell^2} \approx 1.15\,\frac{A_\Omega}{\ell^2}. \]

Equal counts then give the edge length that costs the same as a grid of side \(\Delta\):

Worked example. The 21406 cells of 75 m of the header of step1_minimal.toml (the file does not say if the count includes the inactive cells) cover \(21406 \times 75^2\ \mathrm{m^2} \approx 120\ \mathrm{km^2}\). The same count on a Voronoi mesh means seeds about \(81\ \mathrm{m}\) apart; on a triangle mesh, triangles of about \(114\ \mathrm{m}\) side. These are ideal figures: a real mesh refines near the interfaces, and the count of a run is the number of cells (\(\mathrm{ncpl}\)) of its DISV file.

\(N_S\) counts the cells of the whole raster box, active or not (1. A structured grid); every cell of a mesh lies in \(\Omega\).

Assumptions#

  • A cell has one top and one bottom. The surface inside the cell is flat.

  • A mesh is fixed for the run. It does not move with the water table.

  • The conductivity is isotropic in the plane. The code writes no input for horizontal anisotropy.

  • The coordinates are in a projected CRS in metres. The merge of the vertices of the dual (1 mm) and every size of the mesher read this.

  • The zonal rule treats a channel pixel as a pixel of the stream raster of the delineation. It does not read the observed network.

Limits#

  • No refinement without min_size. With mesh_catchment.zone_meshing.refine_interfaces on and mesh_catchment.zone_meshing.min_size unset, the lower bound of the size is \(\ell_g\), and Gmsh raises every size to it (figure of 2. A runtime mesh from Gmsh). In a test with Gmsh 4.15.2, on a \(1000\ \mathrm{m}\) square refined along one side, the mesh had 250 triangles with the lower bound at \(\ell_g\) and 602 with it at 20 m. Set min_size at or below interface_size.

  • The dual does not follow the constraints. It keeps the outline of the domain, not the river traces or the geology interfaces. A cell can hold both sides of an interface.

  • A mesh bundle written for the triangles does not fit the dual. The bundle holds one conductivity per triangle, and the dual has about half as many cells. The code then logs a warning that ends with Configure K in [flow] or set grid_dual='triangle' to reuse the bundle. and ignores the bundle value.

  • No shape check. A sliver, an abrupt change of size or a high non-orthogonality does not stop a run. The non-orthogonality is the only shape measure the code reads, and it decides about XT3D, not about the mesh. connection_nonorthogonality_deg and nonorthogonality_summary can be called on any planar HydroMesh for a closer look.

  • MODFLOW-NWT is structured. Its zonal top needs modflownwt.sgrid.top_sampling.channel_source at "none": the file is refused otherwise.

  • Boussinesq ignores grid_dual and the top sampling. It works on the triangles.

  • Gmsh is not reproducible. Two builds of the same input give meshes with different cell counts. The mesh cache, mesh_catchment.cache, pins the first one (hydromodpy/spatial/mesh/mesh_cache.py).

  • Not a 3D mesh. The layers are an extrusion of the plan. A footprint that changes from one layer to the next, or a refinement in depth, is not represented.

  • An outlier thickness only warns. A nodata value read as an elevation gives a cell that is kilometres deep, with a clean top, and the run converges. The warning of 8. The checks the code applies is the only sign, and a structured grid does not emit it.

The keys of the structured grid are in [modflow6] and those of the runtime mesh in [mesh_catchment].
