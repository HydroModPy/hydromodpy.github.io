The whole file as a tree#

Type a few words: every word must match, and a key whose name matches comes first.

    • [edition] 1 The set of defaults the file is read with.
      • Open the page of [edition]
    • [workflow] 3 Workflow configuration: workflow.mode ('simulation', 'calibration' or 'overview'), the console verbosity and the profiler.
      • Open the page of [workflow]
      • mode = ‹"simulation" | "calibration" | "overview"› What hmp run does with the file.
      • verbosity = "normal" How much the run prints on the console.
      • profile = false Profile the run with pyinstrument (honored by the hmp CLI; the --profile flag wins over this field). true writes <config>.profile.html next to the config; a string sets the HTML report path.
    • [workspace] 4 Where the shared input data of the project are read and cached.
      • Open the page of [workspace]
      • project_root = ‹path or UPath› requiredFolder of the project, set by the loader: the folder that holds project.toml, else the folder of the file.
      • root = "../.." Explicit shared data workspace root.
      • data_dir = ‹path› Folder the input data are read from and downloads are cached in.
      • products_cap_mb = 5000 MBSize cap of the product store under .hmp/products/, in megabytes.
    • [site] 4 The catchment this project models: its name, label, gauge and registry URI.
      • Open the page of [site]
      • name = "nancon" requiredName of the catchment: letters, digits and underscores, case kept.
      • label = "Le Nançon à Lécousse" Readable name of the catchment, shown in reports, figure footers and tables.
      • gauge = "J0014010" Station that measures the catchment, written once for every key that names it.
      • uri = "hubeau:J0014010" Identifier of the catchment in a public registry, written hubeau:<station code> or bdtopage:<code>.
    • [sites] 26 The catchments of a campaign and the recipes run on each of them: the plan is sites x recipes, one case <site>-<recipe> per pair.
      • Open the page of [sites]
      • table = "sites.csv" Site table, one row per catchment: CSV, Parquet or GeoPackage, relative to the project root.
      • recipes_table = "recipes.csv" Recipe table, one row per recipe: a CSV with a mandatory 'recipe' column; its other columns are bound by [sites.bind] like the site table.
      • enabled = "enabled" Boolean column of the site table; unset, every row is a site of the plan.
      • include = [] Site names the plan keeps; empty, every site.
      • exclude = [] Site names the plan leaves out.
      • overrides = "site_overrides/" Folder of per-site overlays, relative to the project root: <folder>/<site>.toml is applied to every case of that site when it exists.
      • bind = {} Config keys filled from table columns: a quoted dotted path, the grammar of hmp run --set without index, mapped to a column, or to a list of columns for a list key.
      • [sites.recipes.<name>] 2 A recipe written inline: a TOML file and the keys it sets on top of it.
        • Open the page of [sites.recipes.<name>]
        • file = "project.toml" requiredTOML file the recipe starts from, relative to the project root.
        • set = {} Keys this recipe writes on top of its file, as quoted dotted paths ("flow.param.K.field.value" = 2e-5), the grammar of hmp run --set, without index.
      • [sites.run] 5 How the cases run side by side.
        • Open the page of [sites.run]
        • parallel = 8 -Total budget of solves that run side by side.
        • on_error = "warn" What a failed case does to the launch.
        • threads_per_case = 1 -Threads one case may use, applied by the case process itself to its numerical libraries and its child processes.
        • keep_attempts = 1 -Earlier attempts of a case kept under runs/<case>/attempts/ when a fresh attempt starts.
        • prepare_parallel = 2 -Cases prepared side by side before the solves: the geography and the data of each case.
      • [sites.summary] 7 What summary/ tabulates and draws.
        • Open the page of [sites.summary]
        • metrics = ["nse"] Metrics of each case put in the summary tables, scored by the metric rule.
        • rank_by = "nse" Metric that ranks the cases of a site to pick its best one, by the direction of the metric.
        • parameters = [] Parameters of each case put in the summary tables, calibrated or set.
        • figures = [] Cohort figures drawn under summary/figures/<figure>_<variable>.png: map, distribution.
        • variable = [] Metric or parameter, or a list of them, the cohort figures map and distribute.
        • best = "calibrated" Which case of a site the by-site table keeps as its best.
        • columns = [] Extra columns read from the manifest.json of each run, as dotted paths without index (checks.budget_pct, metrics.nse).
      • [[sites.export]] 5 Exports of the project, one [[sites.export]] block each, under summary/exports/.
        • Open the page of [[sites.export]]
        • table = ‹"by_site" | "by_case" | "catalog"› Summary table to export.
        • runs = ‹"best"› Runs whose variables are exported: the best case of each site.
        • variable = [] Variable, or a list of them, exported from each run, with runs = 'best'.
        • format = "csv" File format of the export, csv unless another is named.
        • file = ‹string› For a table, the file name under summary/exports/ (unset: <table>.<format>); for runs = 'best', the folder of the series (unset: best).
    • [metrics] 3 Where and when a run is scored after it ends: the station (default [site] gauge) and the window.
      • Open the page of [metrics]
      • station = "J0014010" Station the run is scored at.
      • [metrics.window] 2 Dates the run is scored on, as {start, end}.
        • Open the page of [metrics.window]
        • start = "2001-01-01" requiredFirst day the scores count, as an ISO 8601 date.
        • end = "2002-12-31" requiredLast day the scores count, included, as an ISO 8601 date.
    • [publication] 3 Licence, creators and attribution written into every copy hmp publish makes of a result. hmp publish --public refuses a project without a licence.
      • Open the page of [publication]
      • license = "etalab-2.0" Licence of the published results, as an SPDX identifier or a licence name (CC-BY-4.0, etalab-2.0).
      • creators = [] People or bodies credited as creators of the published results.
      • attribution = "Contains data from Hub'Eau." Attribution text the publication carries, for the data it was built on.
    • [geographic] 53 Configuration block for geographic and watershed delineation parameters.
      • Open the page of [geographic]
      • source_mode = "standard" Where the model domain comes from.
      • crs_project = ‹string› Target projected CRS for all outputs (e.g. 'EPSG:2154').
      • dem_correc_type = "fill" How the DEM is conditioned before the catchment is delineated.
      • terrain_engine = ‹string› Flow-routing engine that conditions the DEM and delineates the catchment.
      • domain_extent = "box" Selects the DEM surface used for the domain.
      • write_intermediates = false Keep intermediate rasters and shapefiles on disk after geographic preprocessing.
      • [geographic.catchment] 9 "dem" | "txt" | "from_outlet_coord" | "from_polyg_shp"How the model domain is defined.
        • Open the page of [geographic.catchment]
        • cell_size = "25 m" requiredmGrid cell size in metres used to rasterise the XYZ point cloud.
        • x_outlet = 352400.0 requiredmEasting of the watershed outlet in the projected CRS of the project, in meters.
        • y_outlet = 6788300.0 requiredmNorthing of the watershed outlet in the projected CRS of the project, in meters.
        • snap_dist = "150 m" requiredmWidth (metres) of the square window the outlet is moved inside, centred on the declared coordinate.
        • buff_area = "10%" requiredMargin around the watershed polygon.
        • polyg_shp_path = "watershed.shp" requiredPath to the watershed polygon shapefile.
        • dem_resolution = "75 m" mCell size the DEM is aggregated to before anything is delineated, a length ('75 m', a bare number in metres).
        • kind = "dem" Catchment defined by the DEM raster extent.
        • snap_method = "window" Where the outlet lands inside the window of snap_dist.
      • [geographic.capped_breach] 2 Limits of the 'capped_breach' conditioning: max_depth (default 0.5 m) and max_distance (default 200 m).
        • Open the page of [geographic.capped_breach]
        • max_depth = 0.5 mLargest cumulative lowering, in metres, of one breach path (the 'max_cost' of Whitebox): the lowering summed over the cells of the path, not the depth of one cell.
        • max_distance = 200.0 mLongest breach path, in metres.
      • [geographic.synthetic] 16 Synthetic geographic support used when source_mode='synthetic'.
        • Open the page of [geographic.synthetic]
        • case_id = "flat20" Identifier used by local case runners and outputs.
        • [geographic.synthetic.grid] 8 Synthetic grid definition (extent and cell size).
          • Open the page of [geographic.synthetic.grid]
          • length_x = 100.0 mTotal domain length along x (meters).
          • length_y = 1.0 mTotal domain length along y (meters).
          • nx = 100 -Number of grid cells along x, over length_x.
          • ny = 1 -Number of grid cells along y, over length_y.
          • xmin = 0.0 Lower x coordinate of the support extent.
          • ymin = 0.0 Lower y coordinate of the support extent.
          • crs = "EPSG:2154" Projected CRS attached to synthetic outputs.
          • nodata = -9999.0 Nodata sentinel exported to raster artifacts.
        • [geographic.synthetic.topography] 7 "flat" | "linear" | "radial_island"Synthetic topography definition (shape, elevations, slope).
          • Open the page of [geographic.synthetic.topography]
          • kind = "flat" Analytical topography law: 'flat' keeps one constant elevation.
          • base_elevation = 20.0 mElevation of the flat ground surface, in meters.
          • right_to_left_amplitude = 0.0 Additional elevation reached on the left boundary relative to the right boundary.
          • island_radius = ‹number or "<n> m"› mCircular shoreline radius (metres).
          • crest_elevation = 10.0 mCentral island elevation (m).
          • center_x = ‹number or "<n> m"› mOptional x coordinate (metres) of the island center.
          • center_y = ‹number or "<n> m"› mOptional y coordinate (metres) of the island center.
      • [geographic.river_network] 9 Optional DEM-derived river-network extraction settings.
        • Open the page of [geographic.river_network]
        • enabled = false Enable DEM-based river-network extraction from flow accumulation during geographic preprocessing.
        • threshold_mode = "area_km2" Stream-initiation threshold selector.
        • threshold_area_km2 = ‹number› km2Contributing area threshold (km^2), required when threshold_mode='area_km2'.
        • threshold_cells = ‹number› -Number of upstream cells a cell must drain to start a stream.
        • prune_short_streams = false If true, remove short stream segments after extraction.
        • min_stream_length_m = 0.0 mMinimum stream length (metres) used by short-segment pruning.
        • compute_strahler_order = true Compute Strahler order raster from extracted streams.
        • compute_stream_links = true Compute stream-link identifier raster from extracted streams.
        • all_vertices = false Forwarded to Whitebox raster_streams_to_vector.
      • [geographic.enforce_lakes] 2 Optional lake footprint polygons that the crossing notch and the bed regularisation leave alone.
        • Open the page of [geographic.enforce_lakes]
        • enabled = false Read the lake footprint polygons of lake_geometry_path as lakes of the ground, so the crossing notch and the bed regularisation leave them alone.
        • lake_geometry_path = ‹path› Lake footprint polygons (gpkg/shp).
      • [geographic.crossings] 7 Optional notch of the ground at the roads, railways and bridges that cross the generated channel tree: the embankment is lowered to the bed level read on both sides, and the catchment is delineated again on the notched ground.
        • Open the page of [geographic.crossings]
        • enabled = false Notch the ground at the crossings of the channel tree with the declared structures, then delineate again on the notched ground.
        • path = ‹path› Vector file of the structures, with the columns 'kind', 'source', 'name' and 'drop_m' of the crossings data variable.
        • kinds = ["road", "railway", "bridge"] Structure kinds to notch.
        • notch_width = 10.0 mWidth of the notch across the embankment, in metres.
        • bed_reach = 50.0 mDistance along the channel, on each side of the crossing, where the bed level is read, in metres.
        • max_depth = 3.0 mLargest lowering of any pixel, in metres.
        • snap_radius = 30.0 mA point structure (a bridge of the ROE) farther than this from the channel tree is ignored, and so is a channel pixel farther than this from its crossing, in metres.
      • [geographic.bed_regularization] 2 Optional least-change regularisation of the channel bed in the model top, on the pixels of the generated channel tree: the bed never rises downstream, crossing notches are gaps and declared weirs are drops.
        • Open the page of [geographic.bed_regularization]
        • enabled = false Regularise the channel bed of the model top: the least-change fit of the ground that never rises downstream along the channel tree, with the crossing notches as gaps and the declared weirs and dams as drops.
        • min_slope = 0.0001 -Minimum drop of the fitted bed per metre along the channel (m/m), given to the flats the fit pools.
    • [domain] 29 Domain configuration: the depth of the aquifer ([domain.depth_model]), its layering ([domain.layers], read by every solver) and the spatial-support mode used for heterogeneous parameter mapping (none, geology, or zones).
      • Open the page of [domain]

      • [domain.supports.<name>] 10 "generated_bands" | "generated_rings" | "catchment_zones" | "geology"

        • axis = "x" Axis the bands are cut along.
        • coordinate_mode = "relative" How the coordinates of this support are read: as shares of the domain from 0 to 1 ('relative'), or as lengths converted to metres ('absolute').
        • breaks = [] Ordered break coordinates delimiting consecutive bands.
        • labels = [] Ordered band labels.
        • radii = [] Ordered ring radii delimiting consecutive concentric zones.
        • source_zone_id = "catchment" Domain zone id providing the source catchment zonation.
        • default_cell_samples_per_axis = 8 -Sub-sampling resolution per cell axis used when rasterizing band masks.
        • center_x = ‹number or "<n> m"› mOptional x coordinate of the ring center (projected metres).
        • center_y = ‹number or "<n> m"› mOptional y coordinate of the ring center (projected metres).
      • [domain.depth_model] 6 "constant_thickness" | "flat_substratum" | "raster_substratum" | "raster_thickness"Vertical domain model configuration.
        • Open the page of [domain.depth_model]
        • kind = "constant_thickness" Depth-model kind discriminator.
        • thickness = 50.0 mConstant aquifer thickness applied below topography (canonical metres).
        • substratum_elevation = 0.0 mFlat substratum elevation applied over the full domain (canonical metres).
        • offset = 0.0 mVertical shift added to the substratum everywhere (canonical metres).
        • min_thickness = 1.0 mSmallest aquifer thickness kept under the top (canonical metres).
        • scale = 1.0 -Factor applied to the thickness raster (dimensionless).
      • [domain.layers] 12 How the aquifer between the top and the base set by depth_model is split into layers.
        • Open the page of [domain.layers]
        • genmtd_lay = "constant" How the aquifer thickness is split into layers: equal layers, layers that thicken with depth, the fractions you list, or one base per layer.
        • nlay = 1 -Number of layers for 'constant' and 'decay'.
        • lay_decay = 2.0 -Ratio of each layer's thickness to the thickness of the layer above it, above 1.
        • lay_proportions = [0.2, 0.3, 0.5] Share of the thickness each layer takes, from the top.

        • [[domain.layers.layer]] 6 The layers from the top, each with its base, for 'surfaces'.
          • Open the page of [[domain.layers.layer]]
          • name = ‹string› requiredName of the layer, for example 'weathered' or 'fissured'.
          • thickness = 30.0 mBase this far below the base of the layer above, or below the terrain for the first layer (canonical metres).
          • depth = 15.0 mBase this far below the terrain (canonical meters).
          • elevation = 50.0 mBase at this elevation, in the datum of the DEM (canonical meters).
