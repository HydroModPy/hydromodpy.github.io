# dem_correc_type = "fill"How the DEM is conditioned before the catchment is delineated.
Path
geographic.dem_correc_type
More

'fill' (default) only raises cells: each closed depression is raised to its spill level, then a small gradient on the flats lets every cell drain. 'breach' mostly lowers cells: it carves a path through the barrier that closes a depression, after raising single-cell pits to their lowest neighbour, with no limit on length or depth and no fill afterwards (least-cost breaching, Lindsay 2016); it changes far fewer cells than 'fill' and can dig deep. 'capped_breach' lowers and raises: it breaches only within the limits of [geographic.capped_breach] (a maximum cumulative lowering and a maximum length, in metres), then fills every depression the limits refused (the hybrid of Lindsay 2016). The depth limit is a sum over the cells of a path, so it does not give the same landscape at every grid resolution. 'fill' is the default because it is the tool of the paper behind the network criterion (FillDepressions, Abherve et al. 2023), and the criterion itself fills the model top on the mesh by a priority flood: one conditioning rule from the DEM to the score.

Values
  • "breach"
  • "fill"
  • "capped_breach"
Accepted
"breach" | "fill" | "capped_breach"

# domain_extent = "box"Selects the DEM surface used for the domain.
Path
geographic.domain_extent
More

'box' (default) keeps the full buffered rectangular support. 'watershed' / 'watershed_buff' select the catchment (optionally with a buffer ring) surface. Note: the MODFLOW 6 mesh still covers the buffered box (the buffer stays active for inter-basin exchange); out-of-watershed drainage is kept out of the catchment discharge by the DRN watershed-routing, not by an idomain mask. Experimental.

[geographic.catchment]#

How the model domain is defined.

Connections found in the code (3)
  • The code says data.dem.sources: geographic.catchment.catch_def is required when [[data.dem.sources]] is the DEM source. Add a [geographic.catchment] table with catch_def.
  • The code says data.dem: [data.dem] rge-alti at resolution_m = 1 cannot bootstrap the project: the ... km box around the outlet would need billions of pixels. The 1 m grid is for an explicit extent (the fetch_rge_alti helper or `hmp data get`). Use resolution_m = 5, or give [geographic].dem_init_path a file.
  • The code says geographic.crossings.path: A crossings API source can only feed the notch when geographic.catchment.x_outlet / y_outlet are declared, since the watershed that would otherwise give the download box is not delineated yet. Declare geographic.crossings.path explicitly instead.

catch_def selects the shape of this table. One tab per shape, the default first.

The routing surface, the catchment, the mesh and the model top all take it. Unset keeps the pixel of the DEM file, which is what the mesh follows otherwise: 25 m for a BD ALTI download. Aggregation only: each coarse cell is the mean of the fine pixels it covers, nodata left out, on a grid aligned on the upper-left corner of the DEM; a value finer than the DEM's own pixel is refused when the run starts. The DEM file is not changed, the aggregated copy lives in the geographic products of the run.

More

A percentage ('10%') enlarges the catchment AREA by that share, the rule of Abherve et al. (2023): the distance is solved on the real polygon, then snapped to the DEM grid. A length ('500 m', '2 km') is an explicit distance. A bare number (10) keeps the rule of version 1, 10 per cent of sqrt(area in km2) km, about 50 per cent more area on a real catchment, and warns: it lets a sealed run replay its domain.
