[[calibration.phases]]#

One stage of a calibration that runs in several.

  • calibration.phases [[array of tables]] · optional · 26 user keys

Repeat the table: one [[calibration.phases]] block per item.

Connections found in the code (1)
  • The code says calibration.parameters: [calibration.parameters....] points at ..., which is a stage boundary and not a dimension a search may move: it says which model the stage runs, not a property of that model. Declare it in a phase's [calibration.phases.overrides] instead, which is how a two-stage method makes one stage steady and the next transient.

More

Unset, it follows from what the phase scores: 'bisection' when the phase moves one parameter in log space and every one of its blocks is signed (distance_gap), since the answer is then a zero to find; 'scipy_nelder_mead' otherwise, a cost to minimise. hmp calibrate --list-phases prints the method and why. Write it to depart from that choice, and whenever method_options are given. Built-ins: 'grid' (regular sweep, sized by method_options.points_per_dim), 'lhs' (stratified Latin hypercube, sized by method_options.n_samples), 'random_search', 'bisection' (root of a signed criterion on one parameter, the stream-network stage), 'optuna' (TPE), 'cma_es', 'scipy_de', 'scipy_nelder_mead', 'gp_mapping', 'da_mh_gp'. An unknown name is refused when the optimizer is built, with the list installed here.

Accepted

Each engine's own stopping option is written from it, so the same number survives a change of engine, and the engine's own option stays available for reproducing a published call verbatim. # objective = ‹"rmse" | "nse" | "kge" | "mae" | "nse_log" | "nse_delta" | "nse_seasonal" | "reservoir" | "distance_gap" | "distance_mean"›Metric scoring this phase's single simulated series, when the phase does not use objective blocks.
Path
calibration.phases.objective
More

Same vocabulary as a block's 'metric'.

Values
  • "rmse" : Root-mean-square error, in the observed unit; penalizes large misfits most.
  • "nse" : Nash-Sutcliffe efficiency against the observed mean; the standard choice for a level or discharge series.
  • "kge" : Kling-Gupta efficiency; separates correlation, variability and bias when NSE alone is ambiguous.
  • "mae" : Mean absolute error, in the observed unit; less sensitive to outliers than RMSE.
  • "nse_log" : NSE on log-transformed series; weights low flows as heavily as peaks, good for recessions.
  • "nse_delta" : NSE on the increments of the series rather than its level; a level is an integral and can hide flux errors that compensate, which only its increments show.
  • "nse_seasonal" : NSE against the seasonal cycle rather than the overall mean; asks whether the model beats climatology.
  • "reservoir" : Half nse_seasonal plus half nse_delta, built for an impounded level: a plain NSE there is beaten by the seasonal cycle, and the increments are what carry the flux errors.
  • "distance_gap" : Balances the simulated stream network against the mapped one; zero marks the crossing.
  • "distance_mean" : Mean spatial offset between simulated and mapped streams; a diagnostic, not a substitute for distance_gap.
Accepted
"rmse" | "nse" | "kge" | "mae" | "nse_log" | "nse_delta" | "nse_seasonal" | "reservoir" | "distance_gap" | "distance_mean"
# observed_station_id = ‹string›Observed station whose cost the optimizer minimises.

'steady' is one period over steady_window, by default the extent of [simulation.time]. 'transient' is the project's own time grid. Unset, the phase runs the model as the project and its overrides declare it.

Values

Path
calibration.phases.uncertainty.method
See
calibration.uncertainty
Values
  • "cost_profile" : Reads the range of sampled values whose cost stayed within tolerance of the best, off the trace of the search. No extra model run.
  • "multistart" : Repeats the whole search restarts times from different starting points and reports the spread of the optima. It can see a second basin.
  • "linearized" : Linearizes the model about the optimum: one extra run per parameter gives a first-order covariance, and with it which parameters trade off.
