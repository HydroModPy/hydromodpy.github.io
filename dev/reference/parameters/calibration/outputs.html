[calibration.outputs]#

Named observables extracted from each candidate run.

  • calibration.outputs { name = table } · optional · 35 user keys, 3 dev or expert

One table per name you choose: [calibration.outputs.<name>]. The name is free text.

support selects the shape of this table. One tab per shape, the default first.

[calibration.outputs.<name>]
support = "point"Observable extracted at a planar (x, y) point. chosen shape
Path
calibration.outputs.<name>.support
More

'point' reads the variable at (x, y).

Values
  • "point" : Observable extracted at a planar (x, y) point.
  • "boundary" : Observable extracted from a boundary package.
  • "cell" : Observable extracted at one structured cell.
  • "lake" : Observable extracted from a MODFLOW 6 LAK lake state.
  • "network" : The mapped stream network as a calibration target.
Accepted
"point" | "boundary" | "cell" | "lake" | "network"
variable = "head"Simulated variable to extract (e.g. 'head', 'outlet_discharge'). required example value

calibration.outputs.<name>.variable

Example

# observes = ‹string›Station whose loaded record this output is scored against.
Path
calibration.outputs.<name>.observes
More

The record is aligned on the simulated timestamps, so a weighted block scores dated observations rather than a vector typed into the file. The data family follows 'variable': discharge from hydrometry, head from piezometry, stage from lake_levels. Mutually exclusive with 'observed_values'. The station is located by its own record and not by coordinates written beside it, so this output and the single-metric route read the same cell and their costs are comparable; a station the project cannot locate is refused by name rather than scored on another quantity.

# snap_radius = ‹number or "<n> m"›Opt-in. m
Path
calibration.outputs.<name>.snap_radius
More

Move this gauge onto the cell that drains the most within this radius, before it is scored. Accepts a bare number (metres) or a pint string like '150 m'; it is a maximum displacement, measured from the gauge coordinate to the cell centres. The drained area is the one the solver routes on the mesh, along the descent D of the build. Only for 'variable' = 'discharge'. With 'observes', a discharge station is then located by the coordinate of its record, which it otherwise is not, and snapped from there. Off by default: a gauge otherwise stays in the cell it resolves to, which may drain a small share of the catchment, and the run logs that share.

Accepted
number or "<n> m" (a bare number is read in the canonical unit)
Unit
m
Only if
support = "point" | "cell"

True is the paper: its distances are traced by WhiteboxTools on a D8 pointer, and the delineation that produced the catchment uses one too. False descends over shared edges only, four neighbours (D4), and departs from the paper. Path
calibration.outputs.<name>.observed_rasterization
More

'crossing' keeps the cell holding each point where a line crosses the segment joining two edge-sharing cell centres. On a structured grid it reproduces WhiteboxTools VectorLinesToRaster, the paper's tool, and draws the map one cell wide like the simulated network, so a model that matches the map scores J = 0. 'touch' keeps every cell the line touches, corners included, and replays a session made before 2026-09; it thickens every diagonal step of the map and departs from the paper. 'heads' keeps only the free ends of the map whose largest drained area within heads_snap_radius does not exceed that of the other end of their reach, lands each on a nearby cell and draws the rest down the criterion's own descent: the field ditches and rectified reaches below a head stop counting as model error, and the drawn map reaches the outlet. Keep 'crossing' for a map that is not a tree: canals, braids, polders, karst.
