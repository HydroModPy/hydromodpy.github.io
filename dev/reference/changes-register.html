Register of changes#

The register is the file hydromodpy/schema/changes.toml. One row says one change that a reader of an older run or an older file has to know about. The code reads the same rows that this page lists. The label of a run reads the bugs. The loader and hmp doctor --fix-config read the key moves of the configuration. The Numbers section of the changelog is generated from the bugs, the defaults and the recipes that change a number. Nobody writes this page: a row added to the register shows up here at the next build.

A key that only a pre-release of 2.0 wrote has no row. It is refused since 2.0.0 with a message that names every such key of the file, as Versions and stability says.

Bugs#

A fix that changes the numbers of a run. A run of one of the listed versions is labelled exploratory when it exposes one of the listed quantities.

What changed

hubeau_qixm_discharge

2.0.0

>=2.0.0a1,<=2.0.0rc1

source@hydrometry_hubeau

Hub’Eau product QIXM (monthly maximum instantaneous discharge) was read as a water level in m, with the l/s value unconverted. It is now a discharge in m3/s, 1000 times smaller. QixM, which Hub’Eau does not serve and which returned no observation, is read as QIXM.

hubeau_named_stations_capped

2.0.0

>=2.0.0a1,<=2.0.0rc1

source@hydrometry_hubeau

With station_ids and max_stations both set, Hub’Eau hydrometry loaded only the first max_stations named stations that had data and never said so. max_stations now counts only the stations a search over the extent finds, and every named station is loaded.

hubeau_cache_ignores_product

2.0.0

>=2.0.0a1,<=2.0.0rc1

source@hydrometry_hubeau

Hub’Eau cache looked up cached series without product in the cache key. An entry whose product differed answered anyway.

discharge_scores_before_period_alignment

2.0.0

<2.0.0a1

metrics

A stress-period stamp was compared with the observed value at the stamp instead of the mean of the period it closes, so discharge scores (NSE, KGE, RMSE) of these runs are not comparable with later ones.

voronoi_nwt_boussinesq_fixes_2026_10_09

2.0.0

<2.0.0a5

mesh@voronoi, fluxes@modflow_nwt, heads@boussinesq, fluxes@boussinesq

MF6 wells and sides were placed on the triangulation instead of the Voronoi dual cells, MODFLOW-NWT stored one slice per time step and read a wrong budget, and Boussinesq ignored the steady first period, the bed thickness of drains, the recharge rule of fixed-head cells and the sub-steps; fixed between c14c1b4c6 and 48d7db46e.

mf6_computation_top

2.0.0

<2.0.0a5

heads@modflow6, fluxes@modflow6

The MODFLOW 6 DISV took the ground as its top, so the top layer had an uneven thickness and heads under a varying thickness were off by 0.16 to 0.31 m on the Nancon; the DISV now carries a computation top, fixed between b1fa87021 and ec7f8de88.

restart_read_the_rounded_head

2.0.0

>=2.0.0a1,<=2.0.0rc1

start@restart_from

A run started from flow.restart_from read the last head of the earlier run as stored, rounded to 2^-17 under the compact precision, up to 0.8 mm on 100 m of head. It now reads final_state, in double precision.

cyclic_spinup_restarted_the_lake

2.0.0

>=2.0.0a1,<=2.0.0rc1

start@spinup_cyclic_lake

The cyclic spin-up carried the heads from one cycle to the next and restarted every lake from its initial_stage, so the lake never settled. Each cycle now starts from the final stage of the previous one.

mass_balance_percent_error_rounded

2.0.0

>=2.0.0a1,<=2.0.0rc1

fluxes@modflow6, fluxes@modflow_nwt

The percent_error of the water mass_balance of a stamp that closes one time step was copied from the PERCENT DISCREPANCY column of the listing, which MODFLOW prints to 0.01 %. It is now recomputed from IN - OUT and the totals, as for a stamp of several steps. On example 05 (Gouville, 366 daily steps) 365 steps read 0.00, they now read a median of 3.2e-4 %, and the largest stays 0.13 %.

gwt_concentration_saved_every_step

2.0.0

>=2.0.0a1,<=2.0.0rc1

heads@modflow6

MODFLOW 6 GWT saved the concentration at every time step, so a run with sub-steps stored more slices than periods and slice k of the concentration was not period k. It now saves the last step of each period, as the head. On example 09 (Naizin, 12 monthly periods of 5 steps) the store goes from 60 to 12 slices, each equal to the old slice 5k + 4, and time = -1 read slice 12 of 60, in March, instead of the end of December.

gwt_solute_balance_without_storage

2.0.0

>=2.0.0a1,<=2.0.0rc1

fluxes@modflow6

The solute mass_balance of a MODFLOW 6 GWT run left storage_in and storage_out at 0 and copied the discrepancy rounded to 0.01 %. They now hold the STORAGE terms of the listing, and the discrepancy is recomputed from IN - OUT. On example 09 (Naizin) the January row reads storage_in 0.0390 kg/s and percent_error -1.3e-6 % instead of 0 and -0.00.

modpath_tracks_in_grid_coordinates

2.0.0

>=2.0.0a1,<=2.0.0rc1

fluxes@modflow_nwt

MODPATH pathlines and endpoints were stored in the coordinates of the grid, counted from its lower left corner, while the mesh and the MODFLOW 6 PRT tracks are in the CRS of the project. The corner is now added back: on example 00 (Aber) every x moves by 150562.5 m and every y by 6856762.5 m, and the tracks lie on the catchment. Travel times do not change.

outlet_snap_ignored_the_catchment

2.0.0

>=2.0.0a1,<=2.0.0rc1

fluxes@modflow6, fluxes@modflow_nwt, metrics

The outlet of the basin of D was the most drained cell within two rings of the snapped point, whether or not it lay in the delineated catchment. Where the river goes on below the outlet, it closed on a cell outside the polygon and the basin took in the strip around the river. The search now keeps the cells of the polygon when the window holds some. On example 00 (Aber) the basin goes from 502 cells to the 426 of the polygon, and the January discharge from 1495 m3/day to 1146 m3/day.

project_run_reused_a_model_phase_built_otherwise

2.0.0

>=2.0.0a1,<=2.0.0rc1

heads@modflow6, fluxes@modflow6, heads@modflow_nwt, fluxes@modflow_nwt, heads@boussinesq, fluxes@boussinesq, heads@linear_reservoir, fluxes@linear_reservoir, mesh@regular, mesh@triangle, mesh@voronoi, mesh@catchment, metrics

A second Project.simulate on one project reused the catchment, the data and the mesh of the run before, even when its set changed a section they are built from, such as geographic, data or mesh, and a changed simulation.time kept the time grid of the project. Such a run sealed the model of the run before under its own configuration. On example 00 (Aber), simulate(set={“geographic.catchment.buff_area”: “30% of sqrt(area)”}) after a first run sealed 980 cells, it now seals the 1 548 cells of the same run made in one go, with the same values and solution key. A plain simulate after it is back to 980 cells, and a simulate that ends the year on 2017-06-30 seals the values of the same run made in one go.

lake_switched_on_kept_the_mesh_before

2.0.0

>=2.0.0a1,<=2.0.0rc1

heads@modflow6, fluxes@modflow6, mesh@triangle, mesh@voronoi, metrics

A change that switched a lake, a cutoff wall or a flow barrier on or off, or moved its line, kept the mesh built before it, in a second Project.simulate and in the lab. Such a run sealed the mesh of the run before under its own configuration, with the same solution key as a run made in one go. On the island of the tests, a lake switched on after a run without it sealed 130 cells, it now seals the 477 cells of the same run made in one go. Switching on a stream boundary rebuilds a mesh read from a file too.

network_fields_read_the_complete_map

2.0.0

>=2.0.0a1,<=2.0.0rc1

fields@network_agreement, fields@downslope_distance

The fields network_agreement and downslope_distance of a run compared the simulated network with the complete map, whatever map the calibration scored. They now read the map in the cost of the sealed output, the permanent one under map.calibrate_on = “permanent”. On a run that sealed several network outputs they read the output and the window of the phase that promoted it, where they read the first output. On a 64.6 km2 catchment calibrated on the permanent map, the cells mapped only go from 966 to 128, the count of the best trial. No sealed number moves, the two fields are rebuilt when read.

Recipes#

A computation or a rule that changes without a bug. The effect says what it touches: the numbers, a refusal, the label of a run, the identity of a run or the layout of its folder.

Id

Since

Effect

Quantities

What changed

seal_digests_the_field_store

2.0.0

identity

none

The seal of a run gives the sha256 of its field store fields.zarr, over the path and the content of every file, so hmp doctor reports a store changed since the seal. A seal written by a pre-release has no digest for the store, which still reads and is not checked.

run_version_after_an_underscore

2.0.0

layout

none

A second run of one name takes the folder <name>_v2, where it took <name>.v2, so a file exported from it, such as <name>_v2_fields.nc, has one dot, before its extension. A name a person writes never ends in _v<N>: [simulation] name = “calib_v2” is refused with what to write, and a file calib_v2.toml names its run calib-v2. A folder <name>.vN left by an earlier build still opens under its name and is no longer counted as a version of <name>.

netcdf_export_is_a_mesh_qgis_reads

2.0.0

layout

none

A NetCDF export of a model of one layer writes its fields without a layer dimension, with a scalar variable layer. It states its CRS on the variable crs as MDAL reads it (epsg, then wkt in WKT1), and writes idomain as a 32-bit integer. QGIS opened such a file as a mesh with no CRS, left out every field that had layers, and dropped the whole mesh once one field was a byte. A model of several layers keeps its layer dimension. No value changes.

transient_storage_switched_on

2.0.0

refusal

none

A transient [flow] that declares parameters but no Sy or no Ss takes Sy = 0.05 and Ss = 1e-5 1/m as homogeneous fields, with a warning that names the values, and its resolved config writes them. Such a file was refused when MODFLOW was built. A steady flow is unchanged.

frozen_replay_is_never_skipped

2.0.0

refusal

none

hmp run –frozen on the config.toml of a completed run replays it without –force. It used to be skipped as identical to the run it replays. A run that replays no sealed record is still skipped when a completed run is identical.

modflow_steady_start_ignores_boussinesq_runtime

2.0.0

numbers

heads@modflow6, fluxes@modflow6, heads@modflow_nwt, fluxes@modflow_nwt

The auxiliary steady solve that sets the initial heads of a MODFLOW 6 or MODFLOW-NWT run with [flow.ic] kind = “steady_state” always starts from the top of the model. It used to start 0.01 m below the top when [flow.runtime] set backend = “petsc” and surface_interaction_model = “vi_obstacle”, two Boussinesq settings that MODFLOW does not use. Only that combination changes, by the order of the head closure of the auxiliary solve (at least 1e-3 m for MODFLOW 6, headtol, 1e-4 m by default, for NWT); no example, reference or validation case uses it.

keys_the_flow_solver_ignores_are_refused

2.0.0

refusal

none

A key the chosen flow solver does not honor is refused when the file is read, from the supports the solver declares, and the refusal names the solvers that honor it. This adds four refusals: solver.sink_fill = true, solver.drain_band_depth_m and solver.drain_conductance_floor_m2_s away from their defaults, and [flow.sinks_sources.etp], all under Boussinesq, which reads none of them. A transport solver whose requires does not name the flow solver is refused at the read too, where a MODFLOW 6 and MODFLOW-NWT pair used to be refused when the plan was built. A sealed run still reads, with a warning.

transport_refused_behind_an_unconverged_steady_start

2.0.0

refusal

none

A transport run is refused with SolverDivergedError when the flow it follows started from a steady solve that did not converge. MODFLOW 6 accepted such a solve when its final water budget was closed, and the transport went on with a warning only. The replay of a sealed run warns instead of refusing. A steady start that converges, a cyclic spin-up and every run without a transport are unchanged.

named_station_without_data

2.0.0

refusal

none

When every named station returns no observation, the variable is refused with DataSourceError.

bare_input_names_refused

2.0.0

refusal

none

Bare file names are no longer looked up in the workspace data folder.

input_path_scheme_refused

2.0.0

refusal

none

Input paths starting with a URL scheme are refused with a message directing users to source = ‘url’.

workspace_input_names

2.0.0

layout

none

An input file can be written workspace:<name>, which reads data/<role>/<name> of the workspace data folder. The frozen config.toml, config.resolved.toml and the inputs of manifest.json write a file of data/<role>/ as workspace:<name>, where they wrote ../../data/<role>/<name>, and they read the data folder [workspace] gives, where they read <workspace>/data.

refinement_zone_input_path

2.0.0

refusal

none

[[mesh.refinement_zone]] path is read as every input file: a relative path from the project root, an absolute path as written, workspace:<name> in data/refinement_zone/. A bare name is refused, where it was looked up in data/refinement_zone/, then in the data folder, then beside the configuration. A run tracks the layer with its digest, with the role refinement_zone.

url_source

2.0.0

layout

none

URL sources download into the data cache as data/<variable>/<variable>_url_<host>_<sha8><suffix>.

resolved_config_carries_edition

2.0.0

layout

none

config.resolved.toml writes edition, the set of defaults the run used, “2.0” today. A resolved file without it reads as edition 2.0.

frozen_replay_reads_a_new_key_at_its_edition

2.0.0

refusal

none

hmp run –frozen no longer refuses a run whose config.resolved.toml does not write a key that a later version added, when that key is at the default of the edition the run sealed. lineage.drift of a rerun lists such keys under new_at_default. A key the sealed file writes with another value is still a difference.

prerelease_forms_refused

2.0.0

refusal

none

A file or a sealed run that holds one of the 175 keys or values only a pre-release of 2.0 wrote is refused, with every such key it holds. This version does not rewrite the file. The list is hydromodpy/config/prerelease_forms.txt, and it leaves in 2.2.0.

stac_and_prov_exports_need_the_annex

2.0.0

refusal

none

hmp export –as stac and –as prov, and [[export]] format = “stac” or “prov”, are refused when hydromodpy_annex is not installed, with the module to install. Both views moved to the annex. RO-Crate stays in the wheel.

data_cache_never_in_the_user_cache

2.0.0

layout

none

A data request or a call without a data folder no longer caches a DEM, a geology map or a crossings layer under the user cache of the machine. The file goes under the data folder of the call, data/ of a project without a workspace, so a file fetched earlier is fetched again, and a newer product version can change the values read.

data_cache_is_its_sidecars

2.0.0

layout

none

The data cache is the sidecar next to each fetched file, and data/cache.duckdb is gone. A sidecar names the variable, the source, the station, the product, the box, the period, the window asked, the sha256, the size and the licence of its file. A station that answered nothing is a sidecar marked empty, without a file. A user file is never a row of the cache.

stale_cache_file_rehashed

2.0.0

layout

none

A cached file whose size differs from its sidecar, or that is newer than its sidecar by more than a second, is hashed again, and is fetched again only when its sha256 changed. A copy of a workspace by cp no longer fetches its files again.

prune_keeps_cited_inputs

2.0.0

refusal

none

hmp data prune never removes a file whose sha256 a sealed run, a kept trial or a lockfile of the workspace cites, and names each one it keeps. When the inputs of a run or a lockfile cannot be read, it removes nothing.

former_data_cache_refused

2.0.0

refusal

none

A data folder that still holds data/cache.duckdb of a pre-release of 2.0 is refused with a sentence that names hmp workspace clean –data-cache, and a lockfile hydromodpy.lock.v1 is refused with a sentence that names hmp data lock. Neither is read.

frozen_replay_pins_empty_answers

2.0.0

refusal

none

hydromodpy.lock pins a station that answered nothing as an input with empty = true and no sha256. hmp run –frozen replays such a station when the lockfile pins it, refuses an empty answer the lockfile does not pin, and refuses a file for a station the lockfile pins empty. In a pre-release every empty answer was refused under –frozen, because the lockfile could not pin it.

request_identity_composition

2.0.0

identity

none

A run is now told identical to a completed run by its request, the configuration as written with its edition and the digest and state of every input it reads, plus the code, the solver binaries and the numeric packages that compute it. The address of a URL and the path of a file no longer count, their bytes do. A run or a calibration that a pre-release would have skipped runs once again.

json_paths_need_a_base

2.0.0

refusal

none

A configuration given as a dict or as JSON text reads its relative paths from the base the caller names, never from the current folder, and is refused without one. JSON text is read as a file is, with the same refusals.

run_and_project_names_refused

2.0.0

refusal

none

A run name or a project name holds lower case letters, digits, _ and -, forty characters at most, and holds neither a doubled underscore nor a device name Windows reserves. A name written otherwise is refused with the folded name to write. A name the code makes, from a file stem or a case of a plan, is folded in silence and still refused when it is too long or reserved.

stage_products_in_one_store

2.0.0

layout

none

The meshes, and the output of the soil reservoir, are kept in one product store under .hmp/products/, keyed by what they read and by the code that computes them, under the cap [workspace] products_cap_mb. The mesh cache of a pre-release under .hmp/mesh_cache/ is no longer read, so a triangle mesh is drawn once more, the same mesh with the same gmsh.

dem_header_contract

2.0.0

refusal

none

A DEM that breaks the header contract is refused before routing: no CRS, a CRS that is not projected or not in metres, a rotated grid, pixels not square within 1 %, a routed resolution outside 1 to 250 m, elevations outside -500 to 9000 m, or an outlet outside the raster or on a nodata cell.

terrain_product_store

2.0.0

layout

none

The corrected DEM, the D8 directions and the D8 accumulation are now a stage product under .hmp/products/, keyed by the DEM digest, its state, the conditioning method and the terrain engine; a rerun reads the stored terrain instead of rebuilding it.

solve_time_leaves_the_tables

2.0.0

layout

none

The wall time of the solve is no longer a row of metrics.parquet nor of the seal. It is in profile.json, with the time of every step. A run of a pre-release keeps its row, and show reads it.

restart_head_written_exact

2.0.0

numbers

heads@modflow6, fluxes@modflow6

The start head of a run that restarts from another one is written to MODFLOW 6 as a double precision binary array, and its lake stages with all their digits, no longer rounded as text. Heads move by about 1e-9 m and lake stages by up to 5e-9 m.

recharge_forcing_is_a_rate

2.0.0

numbers

fluxes@modflow6, fluxes@modflow_nwt, fluxes@boussinesq

Run.recharge_forcing() returned the mean over the active cells of the recharge volume of each cell, in m3/s. It now returns the rate over the domain, the volumes summed and divided by the area of the active cells, in m/s. On a mesh of equal cells this divides the old value by the cell area: on example 04 (cells of 5 625 m2) February 2000 goes from 5.10e-5 m3/s to 0.78 mm/day. On a mesh of unequal cells a large cell no longer weighs like a small one.

data_inventory_dates_are_measured

2.0.0

layout

none

first and last of data_inventory.parquet held the window a section asked for, and on a station row the window of the request. They now hold the first and the last date that carries a value. The asked window is kept only for a record without dated values, a field for instance.

restart_reach_stage_under_sfr_storage

2.0.0

numbers

heads@modflow6, fluxes@modflow6

MODFLOW 6 with SFR storage: a run that restarts from another one, and each window of a chain, gives each reach the stage it ended on as INITIALSTAGES, read from final_state, where the reach used to start from the stage the package computes. On a two-window chain the head of window 2 moves by about 1e-4 m, and the chain then differs from the run in one piece by 6e-10 m. A source run of a pre-release of 2.0 has no final_state, and its reaches start as before.

seal_v4_one_model

2.0.0

layout

none

A run seal and a job seal are one document, manifest_version = 4 with profile = “run” or “job”. A run seal carries the digests of its values and one lineage block, and its identity names the run by solution_key and request_id instead of config_hash; a job seal carries the request id, the process and the input set it read. A version 3 run seal and an hmp-manifest/v2 job seal are read in memory, and the file is never rewritten.

seal_hashes_the_values

2.0.0

identity

none

A run seal carries one values/1 digest per array of fields.zarr, per array of final_state/ and per floating column of every table, simulation and parameters included, with the wall-clock row of metrics left out. A field rounded at write time is hashed on the float64 values the writer received, kept per step in the facts of the run. Two runs of the same values seal the same digests, verify_artifacts still compares bytes only, and no value of an ordinary run moves.

replay_plays_then_classes

2.0.0

refusal

none
