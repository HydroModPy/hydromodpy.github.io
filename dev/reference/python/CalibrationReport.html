What one calibration found, with or without phases.

hmp.calibrate and Project.calibrate return this class, and with dry_run a plan that runs nothing. A calibration in phases fills phases, each with its own report, and frozen, and its best values are those of the calibrated run. to_dict gives the same summary as a JSON-friendly mapping.

The shape of this report and the [calibration] section are experimental until the rework of the calibration is published.

cost_block_fractions: dict[str, Any] | None = None#

Fraction of the cost each block actually took.

"mean" averages the fraction over the finished trials (each a mapping of block name to its fraction, 0 to 1, of the cost), "mean_n_trials" is how many of them entered that average, and "best" reads the fraction at the reported candidate. None when the phase scores through a single metric with no declared [[calibration.objective_blocks]], or, for a phase reused from a previous run (see extra["cost_block_fractions_absent_note"] when that is why), when its journaled trials carry nothing to recompute it from. See hydromodpy.calibration.optim.objective.cost_block_fractions() for how a fraction is defined.

Where the restarts of each phase landed, when the file asked for restarts.

The calibrated value is untouched: it is the best of them. This says how far apart the others finished, which is the one thing a single search cannot report about itself.

reused_from_disk: tuple[str, ...] = ()#

Names of the phases read back from the reopened session instead of solved.

Only non-empty under hmp calibrate --resume: a phase is reused when it completed in the session and its recorded fingerprint matches this run’s own model, mesh and input files.
