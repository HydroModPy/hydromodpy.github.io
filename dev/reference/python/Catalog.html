class Catalog(
workspace_path,
*,
catalog_path=None,
runs_dir=None,
persistence=None,
read_only=False,
)[source]#

Workspace-level catalog of finished simulations.

Backed by DuckDB for tabular state (simulations, parameters, metrics, provenance, calibration sessions) and by Zarr / Parquet for field arrays and timeseries written under <project>/runs/<run>/.

Inspecting is reading: every caller that only reads (listings, show, SQL queries, figures, reports) opens with read_only=True, which installs no schema, runs no migration and leaves the index file byte for byte as it found it. A writable handle is for code that produces runs.

The facade owns four pieces of state:

  • _db: a CatalogConnection (lazy DuckDB connection released while idle, re-acquired with retry on contention).

  • _workspace: the project catalog root.

  • _paths: a StoragePathResolver translating simulation ids to run directories and the Parquet/Zarr paths they hold.

  • _open_zarr_handles: live SimulationZarr handles, tracked so finalize and close can release them deterministically.

Parameters:

  • workspace_path (Path | str) – Workspace directory, or direct path to a .duckdb catalog file.

  • catalog_path (Path | str | None) – Optional explicit catalog database path.

  • runs_dir (Path | str | None) – Optional directory containing the per-run directories.

  • persistence (PersistenceConfig | None) – Which sinks the catalog writes to (index rows, Zarr fields, Parquet tables) and how they are compressed. Field arrays are always a directory store: there is no packed form.

  • read_only (bool) – Open the index read-only. The database file must already exist: an inspection never creates a phantom index.

Raises:

  • hydromodpy.core.exceptions.CatalogError – If the DuckDB catalog cannot be opened or the schema migration fails.

  • hydromodpy.results.errors.SchemaVersionMismatchError – If the stored catalog schema version is older than the runtime expects.

Examples

>>> import hydromodpy as hmp
>>> catalog = hmp.open("~/hmp_workspace")
>>> latest = catalog.latest()
>>> latest.summary()

hydromodpy.results.run.Run

Per-simulation view returned by catalog queries.

Multi-run view returned by cohort queries.

Catalog.find(**filters)[source]#

Return the runs that match every filter, newest first.

Trashed runs are left out unless status asks for them.

Parameters:

**filters –

Each keyword narrows the set:

  • project, name, name_stem, config_hash, crs_wkt (or crs), geographic_fingerprint: exact value of that run column.

  • solver, solver_category, status, flow_regime, mesh_topology: their code, for example solver="modflow6" or status="completed".

  • tags: one tag the run carries.

  • <metric>_gt, <metric>_gte, <metric>_lt, <metric>_lte: bound on an outlet metric, for example nse_gt=0.7.

Returns:

RunSet – The matching runs. It is empty when nothing matches.

Raises:

ValueError – If a keyword is none of the above. The message lists them.

Return type:

RunSet

Examples

>>> good = cat.find(
...     project="my_project", status="completed", nse_gt=0.7
... )
>>> good.best("nse")

Catalog.resolve(
ref,
*,
project=None,
in_trash=False,
unambiguous=False,
)[source]#

Resolve a user reference to a simulation UUID.

Accepted forms, tried in order:

  1. @-selectors: @last, @last~N (N-th newest completed), @best:METRIC / @worst:METRIC (outlet first, any station as fallback; add @STATION to scope explicitly), @running. Best follows the direction of the metric: highest nse, lowest rmse, pbias closest to zero (see METRIC_SENSE).

  2. Full UUID (36 chars with dashes).

  3. UUID prefix of >= 4 hex characters. Must match a single simulation; raises AmbiguousReferenceError otherwise.

  4. Exact name of a live run (globally, or within project).

  5. name_stem: a bare name resolves to the latest live version of that stem (baseline -> baseline.v3).

  6. Exact name of a trashed run, when no live run answers to it.

With in_trash, a name looks only at trashed runs, under the name the trash listing shows (original_name): it is what restore means. With unambiguous, a name that a live run answers to (rules 4 and 5) while a trashed run still carries it raises AmbiguousReferenceError listing both: a purge must not pick one of two runs the user could mean.

Raises SimulationNotFoundError when nothing matches, with the closest known names and tags suggested.

Catalog.rename_simulation(sim_id, new_name)[source]#

Rename a run: move its directory, then update the row.

The run directory is named after the run, so a rename is a move on disk plus an index update, and the new name has to clear two independent obstacles. A rename never mints a version behind the caller’s back: the name was chosen, so a taken slot is a DuplicateSimulationNameError rather than a different name handed back in silence.

The (name_stem, version_int) slot must be free among the live rows of the project. A bare stem takes version 1, so renaming into a stem that already owns .v1 is rejected rather than creating a duplicate (stem, 1) that would later break if_exists='version'.

The directory must be free in the whole catalog, live or trashed and whatever the project: every project registered in one catalog writes into the same runs/ tree, and trashing leaves the bytes where they are so the run stays restorable.

)[source]#

Delete a simulation row and (optionally) its on-disk artefacts.

With remove_storage true (the default) the hard purge is crash-safe: it journals the intent (purge_journal phase pending + a sim.purge.begin audit row), removes the bytes, then cascade-deletes every per-sim DuckDB table and clears the journal in a final transaction tagged with audit_event_type (sim.delete for routine deletes, sim.purge for hmp privacy purge). Because the simulation row survives until that last commit, no delete/crash sequence can leave a byte under runs/ unreachable: any interrupted purge leaves a purge_journal row that replay_purge_journal() finishes.

With remove_storage false there is nothing on disk to orphan, so the cascade runs in a single transaction with one audit row.

Catalog.write_timeseries_batch(sim_id, records)[source]#

Write a batch of timeseries records to timeseries.parquet in one pass.

records must use the column names of TIMESERIES_SCHEMA: sim_id, station_id, variable, component, timestep, time, value, unit, qflag. Missing keys default to None. Compared to looping over write_timeseries(), this entry point avoids the O(N**2) read/merge/rewrite pattern: the merge happens once against the existing file.

Catalog.write_timeseries_columns(sim_id, columns)[source]#

Columnar fast path of write_timeseries_batch().

columns maps TIMESERIES_SCHEMA column names to equal-length per-row arrays; scalars broadcast and missing columns get the batch defaults. Building the Arrow table from arrays skips the per-record Python loop, which matters for multi-million-row solver series.

Catalog.write_view(sim_id, view_name, records)[source]#

Persist one declared Parquet view of a run into its run directory.

The run directory is the only home these declarations have: an index rebuilt from the runs finds them again through the view, which globs the run directories. sim_id is filled in, and a view whose schema declares crs_wkt / crs_epsg inherits the simulation CRS.

A column the schema does not declare is refused by name rather than dropped: a misspelt key would otherwise write a whole run of nulls and say nothing.
