Changelog#

Every release of HydroModPy and every change since the last one, newest first. The page is the CHANGELOG.md file at the root of the repository, included as it is. It follows Keep a Changelog and Semantic Versioning. Under each release, Added lists new features, Changed lists changes of behavior, Removed lists what was deleted and Fixed lists bug fixes.

The [Unreleased] section is the work merged since the last release. It ships with the next version.

The long development notes of the alphas and of the release candidate are kept in the repository, in changes-during-the-alphas.md. They are not a page of this site.

The keys added, removed or changed in the TOML file between two versions are listed, from the models, in What changed in the TOML. For what a version number promises, see Versions and stability.

Fixed#

  • A [sites] project with one site accepts a site key written in the project file itself, such as the path of a station folder, so a plan on one catchment needs no site_overrides/ file. With several sites the key is still refused, since every catchment would read the same value.

[v2.0.1] - 2026-11-25#

Added#

  • Run.score and RunSet.score score stored runs after the fact, on any window, any metric of the table but the two network distances, and an optional months mask: runs.score(windows={"y2016": ("2016-01-01", "2016-12-31")}, metrics=["nse_log"], months=[4, 5, 6, 7, 8, 9, 10]). The pairing is the one of the seal, so run.score() with no argument gives back the sealed metrics. RunSet.timeseries stacks the series of every run in one table.

  • Run.score_network and RunSet.score_network compute the network criterion of a stored run, with the settings it was calibrated with or the defaults. On a run stored with [simulation.results.persistence] field_precision = "exact" they give the numbers a calibration trial computed at the same parameters. With the default compact precision a cell at the seepage threshold can flip, and the size of that difference is not measured yet. A set builds the map geometry once for the runs that share it.

  • [sites.design] draws a plan of experiments: method (sobol, lhs or grid), n, seed, and parameters.<name> with path, bounds and sampling. Each point becomes a recipe p0001, p0002…, its drawn values are columns of cases.csv, and a larger Sobol n or a new LHS lot keeps the cases already run.

  • hmp.index(ws).score(...) and .score_network(...) score every project of a workspace. The run-set figure parameter_space draws two parameters on log axes, coloured by a score. [[sites.summary.window]] makes hmp campaign collect write summary/scores.parquet.

  • A calibration phase on a fixed plan (lhs, grid) reports the correlation and the axis ratio of its best fifth of trials, which shows a ridge between two parameters.

  • The how-to page “Plan and score experiments” walks through these entry points.

  • A station source of source = "file" can name one chronicle CSV, path = "workspace:recharge_file_NANCON_20000101_20021231_M.csv". It is read with the location file of its folder for the one station of station_ids or of [site] gauge, and that location file is pinned with it by hmp data lock and checked on a frozen replay. hmp publish --package and the example catalog ship the row of its station.

  • hmp check takes --overlay and --set, merged as hmp run merges them, so a model and the site file it runs with are checked together: hmp check project.toml --overlay sites/canut.toml. hydromodpy.check takes them as overlays and set. A [sites] project refuses an overlay and names the recipe or the site file to write it in.

  • Run.hydrographic_network("mesh_constraint") returns the rivers the mesh carries, one line per chain of river cells through their solver centers. hmp compare scores the flowing cells against it beside the mapped networks.

  • The network table of hmp compare now keeps how each row was cut: the field, the active rule, its thresholds, the buffer, the distance rule and, for the mesh row, the contributing area or cell count that traced its streams.

  • [flow.sinks_sources.recharge.soil] method names the storage law of the soil reservoir: fao56 (the law so far, the default), thornthwaite, dingman or edijatno_michel (the production store of GR4J). The sealed share, the curve number, the bypass and the transit work the same under each law.

  • [flow.sinks_sources.recharge.soil.snow] turns on a snow pack melted linearly from 0 to 6 °C, read from [data.temperature]. kc also takes a table {low, high, months} that follows the growing season.

  • The soil budget printed by hmp run --until load_data now gives, when a gauge is loaded, the ru that closes recharge + runoff against the gauge over the run, its range over resampled years and its move under a 5 % bias of the rain or the gauge. Write it as ru, then calibrate K and Sy with it fixed. A calibration phase with regime = "soil" does the same without a solver and freezes ru for the phases after it.

  • [data.etp] formula = "oudin" or "hamon" computes the ETP from [data.temperature] instead of loading it. Every reader of the ETP receives it.

  • [recharge_estimates] runs the recharge methods of ESPERE (BRGM) on the loaded data before the solver: Turc, Guttman and Zuckerman, Kessler, the Wallingford, Chapman and Maxwell and Eckhardt baseflow filters, the water table fluctuation, and the factor that would scale the run’s recharge onto the gauged volume. None enters the model. The run prints them beside its own recharge and writes the table recharge_estimates. The figures recharge_estimates and water_balance_loop read it.

  • [data.impervious] gives the soil reservoir its sealed share cell by cell, from OCS GE of the IGN (source = "ocsge", year pinned), from the built-up class of ESA WorldCover (source = "worldcover"), or from a file. [data.curve_number] does the same for the curve number from a file such as GCN250. Each cell reads the mean inside the catchment, in place of impervious_fraction or curve_number, and writing that value beside its map is refused. On the Nancon the sealed share is 3.95 % with OCS GE 2023 and 2.39 % with WorldCover 2021.

  • [data.recharge] formula = "turc", "guttman_zuckerman" or "kessler" gives a steady run its recharge: the mean over the complete years of the run of the yearly formula on the basin rain. A transient run is refused, since no share of the year is invented.

  • [recharge_estimates] soil_methods = "all" runs every soil law on the run’s forcing, and compare_loaded = true loads [data.recharge] and [data.runoff] (SIM2 for instance) beside a soil run for the comparison only. Their monthly recharge and runoff, the run’s and the weather go to recharge_estimates, drawn by the new figures recharge_signals and recharge_regime. hmp run --until prepare_solver writes them without a solve.

  • [flow.sinks_sources.recharge.soil] infiltration_ratio sends only that share of the water leaving the soil to the aquifer, the RIPE of ESPERE; the rest runs off on the same day and reaches the discharge through the runoff of the run. 1, the default, changes nothing. The soil budget of hmp run --until load_data prints the ratio ESPERE takes from the gauge, the lowest yearly Wallingford baseflow index, for the user to copy: 0.70 on the Nancon over 2015-2020. [data.infiltration_ratio] gives it cell by cell from a file, or from OCS GE with one ratio per cover written in the section; HydroModPy ships no value per cover.

  • [data.curve_number] builds the curve number from a land cover: source = "ocsge", "worldcover", or "land_cover" for a raster of a named legend (cci, worldcover, clc, or custom). Each class goes to one class of the ESA CCI legend and reads its GCN250 row (Jaafar et al. 2019) on the hydrologic soil group the section writes, a letter or a HYSOGs250m map. Sealed and built-up classes stay out, left to [data.impervious]; any row can be overridden under classes. On the Nancon with group C, OCS GE 2023 gives 74.2, WorldCover 2021 76.8, the GCN250 map itself 78.5.

  • The OCS GE department archives now sit once per machine in the user cache, shared by the sealed share, the infiltration ratio and the curve number. A soil map larger than the catchment, such as the global GCN250, is now read only over the window of the forcing grid.

  • A run scores bfi_gap, the baseflow index of the simulated discharge minus the one of the gauge, both by the Wallingford filter on the same days, and a calibration may weigh bfi_error, its absolute value, beside a fit such as nse. It asks whether the stream is fed by its aquifer in the share the gauge shows, and is blind to volume and timing. It reads daily discharge only: a monthly run leaves bfi_gap empty, and the criterion is refused outside a transient run with a daily step.

  • [flow.sinks_sources.recharge.scenario] replaces the loaded recharge by its mean year, with dry years put in a row, to test a sequence of droughts.

  • source = "explore2" reads a DRIAS Explore2 file of projected recharge or runoff under [data.recharge] and [data.runoff].

  • hmp example add takes several ids (hmp example add 00 07 08) or --all, and hmp.example(["00", "07"], add=True) or hmp.example(add=True) does the same from Python. Every id is checked before the first download. The catalog now ships the twelve examples 00 to 11: python -m tools.dev examples manifest takes every folder NN_name of examples/projects/ that holds a project.toml and a README.md, so a new example needs no code. Under --format json the command writes one row per example, schema hmp.example.add.v2, with the new field example_id.

  • hmp catalog gc --solver-files-days DAYS, and Project.gc(solver_files_days=...), removes the solver/ folder that keep_solver_files kept in the sealed runs older than DAYS. The rule is off by default, so the folders stay unless it is asked. The seal never lists them, so the run reads the same without them. On a daily run such a folder can weigh 5.6 GB, beside 195 MB for its fields.zarr.

  • The Parquet views of the index (timeseries, budgets, mass_balance and the Parquet metrics and provenance) now read the kept trials of the sessions too, each row by its sim_id.

  • read_workspace_runs, which reads the runs of several projects without any index, now gives label and rule_version for each run, computed on read as the index does.

  • The sidecar of a sealed share, an infiltration ratio or a curve number built from OCS GE now gives the editions read, one per department, in product_version.

Changed#

  • The index no longer stamps the logs/ and .hmp/ folders of a run, and reads a seal again only when its folder moved. The pulse a live run writes every 30 s made every read of the project write the index again. Catalog.cases now reads the status and the pulse of a live case on the disk.

Fixed#

  • A folder that holds two chronicles of one station, such as recharge_file_NANCON_..._M.csv and ..._D.csv, now stops the run and lists them. The loader used to read the first name in alphabetical order without a word. A chronicle of NANCON_REA is no longer taken for one of NANCON: after the id, a name holds nothing, a step, or two dates and a step.

  • A network calibration whose best trial matches the map exactly, so that D_so = D_os = 0, now seals that trial. The parts of the cost the trial could not define, such as D_so_over_D_os or catchment_mismatch on a domain with no delineated catchment, are written null in checks.calibrated_by.components, where the seal refused the run before.

  • hmp check now names, before the solve, the particle figures (particle_tracks, residence_time_distribution) a run without particle tracking will skip, and each map whose pathlines overlay will be drawn empty. Only the pathlines export was named so far, and a [transport.modflow6_prt] table with no transport entry in [[simulation.process]] went unnoticed until the end of the run.

  • A source = "url" file whose address has no suffix, such as a WCS GetCoverage request, now takes the suffix the server names in Content-Disposition or Content-Type. It was cached as .bin, and Whitebox refused to read it as a DEM. The CRS stamp on a Whitebox output is skipped when the file already holds that CRS: rewriting it made Whitebox fail to read back some GeoTIFFs it wrote, such as a DEM served by GeoServer, on the first run of a project.

  • The relief shade of a map now stops at the active cells. On a catchment with a concave outline it used to leave grey streaks across the bays, outside the mesh, and it shaded the inactive cells of the border.

  • hmp publish --package and the example catalog now ship every data file a TOML names, wherever the key sits. A catchment polygon ([geographic.catchment] polyg_shp_path) and a file read by a boundary condition, such as the sea level of example 05, were left out, so the copy failed on a missing file. A shapefile now travels with its .shx, .dbf, .prj and .cpg; example 00 shipped its stream network as a lone .shp.

  • A grid of data/ that a larger one contains is no longer removed when a sealed run or a lockfile cites it. The skip of an identical run and hmp run --frozen failed once an enclosing catchment was fetched. hmp data prune removes the smaller grid once nothing cites it.

Numbers#

  • With depth_model kind = “flat_substratum”, the aquifer bottom of a DEM pixel without data was set 1 m under the no-data value, so it stopped being read as no data. A mesh that samples the bottom (triangle, voronoi, a regular grid resampled from the DEM) blended it with the flat elevation on the cells next to the mask. With domain_extent = “watershed” these are the cells of the catchment edge: on a 31 km2 catchment at a flat bottom of 15 m, 768 of 779 edge cells had a bottom between -800 and -9 891 m, a column 100 times thicker than the 76 m of the others. A no-data pixel now keeps the no-data value and every sampled cell gets the flat elevation. A constant_thickness model and a regular grid on the DEM pixels do not change.

  • map.drawn_by defaults to “crossing”: the mapped network is drawn on the cells as the data gives it, the rule of the paper, still cut to the catchment. It defaulted to “heads”, which kept only the stream heads of the map and drew the rest down the model’s own descent. A calibration with no pin on the protocol follows 1.4, which differs from 1.3 by this rule alone. A pin on 1.3, or map.drawn_by = “heads” in the network output, gives the heads rule back. A run that sealed no network output draws its network figures by the crossing rule too. A file of edition 2.0 that writes no drawn_by moves with it, at the request of the owner, so its K and costs change wherever heads and crossing draw different cells.

  • On a mesh whose faces follow the lake shores but leave the ring open somewhere (an arm narrower than a cell, a wall that leaves the shore), a lake owns the cells its polygon covers for more than half of their area, each cell whole. It owned every cell the polygon touched, so a ring of land cells one cell wide joined the lake and had its top carved under the highest stage of the abacus. On a reservoir of 200.3 ha whose shore the faces cover at 99.45 %, the lake goes from 1 256 cells and 296.3 ha to 885 cells and 201.3 ha, and the cells it leaves keep their terrain and get their drain back. A mesh that closes every shore, and a mesh without lake faces, do not change.

v2.0.0 - 2026-11-20#

What to do when you update#

  • A run or a session stored by a pre-release (2.0.0a5 and earlier) is refused. Run it again with this version.

  • A file with a key that only a pre-release wrote is refused. The message names the current name of each such key the file holds. This version does not rewrite the file, so edit it with that list. hydromodpy/config/prerelease_forms.txt holds the forms.

  • hmp doctor --fix-config still rewrites the keys that load with a warning.

  • The [display] keys figures, overrides, preset, cmap, backend, show, save and time are refused, each with what to write. Write one [[display.figure]] table per figure, with its options as panel fields, and theme for the look. dpi now defaults to 300.

  • A figure name of a pre-release, such as piezometric_map or seepage_map, is refused with the request that replaces it. The page “Figure requests” of the reference lists the 73 former names.

  • A run sealed before this version still opens and draws with run.figure(...). Its sealed config is refused when it is validated or replayed, so run the file again to replay it.

  • hmp export --regen figures skips a figure that a pre-release recorded and gives the command that draws it now.

  • A Python name or an hmp command that left is refused with the call that replaces it. tests/unit/architecture/surface/removed_names.tsv lists them.

  • If you come from version 1, read docs/source/get-started/from-v1.md. The keys and commands that moved are listed in docs/source/reference/changes.md, “What changed in the TOML”.

  • A file that does not say which calibration protocol it wants follows protocol 1.3.

  • A run written by an earlier version keeps its label. A [[bug]] row of hydromodpy/schema/changes.toml labels exploratory only the runs whose quantities it names.

  • [[export]], [[sites.export]] and [sites.summary] name what they read with variable, the key [[display.figure]] writes, one name or a list. A file that writes variables still loads with a warning, and hmp doctor --fix-config rewrites it. run.export and hydromodpy.export take variable=.

  • A second run of one name is <name>_v2, not <name>.v2. A folder <name>.vN of an earlier build still opens under its name. [simulation] name cannot end in _v<N>, and a file calib_v2.toml names its run calib-v2.

  • The IGN DEM is two sources. source = "bdalti" fetches the 25 m BD ALTI and source = "rgealti" the RGE ALTI at 5 m, or 1 m with resolution_m = 1. A file that writes source = "ign_geoplateforme_dem" with dataset is refused, and hmp doctor --fix-config rewrites it.

Added#

  • The HTTP server sends a file of a project with GET /v1/<org>/<project>/files/<path>, the path an answer gave: an export, a saved figure, a report or a tar from publish. A folder, an absent file and a path or a link that leaves the project are refused.

  • [flow.param.<id>.field_vertical_profile] takes depth_at = "top", "middle", "base" or "surface_then_base" (the ground for the first layer, the base for the others), the depth at which each layer reads its profile, the middle by default as before. An exponential profile takes characteristic_depth_high, ground_low and ground_high: its decay length then goes linearly with the ground elevation from characteristic_depth to characteristic_depth_high, for a weathered zone that thins under the hills.

  • hmp.Lab("project.toml") builds a model in memory one step at a time. lab.advance() plays a step, lab.state shows the objects built so far, lab.steps shows which steps are built, stale or pending, and lab.set(K=5e-5) changes a value so that only the steps that read it play again. lab.force puts an object the configuration cannot say, such as a mesh built by hand, and lab.release takes it back.

  • hmp.Lab(run) opens a run from hmp.open, sealed or with its facts, in the lab, with the configuration the run kept. It builds nothing until lab.advance, and lab.run writes a new run in the same project.

  • hmp.run and Project.simulate stopped from setup_process up to before prepare_solver now give a partial run instead of None, which hmp.open reads too. Its new Run.steps lists the steps done, and reading a field from it says how to resume.

  • A how-to page, Run step by step, shows a run played by windows with a figure before the solve, and a run played again that gives back the run already done.

  • when = "after:prepare_solver" and "after:run_solver" are accepted for a figure whose data is stored by then, such as the topography of a backend that builds a cell column. A figure asked earlier than its data is refused at the check, with the first step that fits.

  • hmp.Lab({...}, base=folder) reads the dict as hmp.Project does, and keeps it as a draft when a section is missing, such as [simulation]. lab.set adds the sections one by one and plays the steps again from the start. lab.advance names the step and the section a draft lacks, lab.run and lab.write_config list what is missing, and no Project run starts from a draft.

  • lab.run() keeps the solve of the lab when run_solver is up to date and nothing is forced, instead of solving again. The seal, the stored heads and the solve count in profile.json are those of hmp.run with the same changes. A project that keeps its solver files solves again.

  • lab.capture records the local variables of a function while the model solves, lab.run keeps the model as a stored run, and lab.write_config writes the configuration with your changes. The lab plays in memory up to run_solver, and a run is refused while an object is forced.

  • An input file can be named in the data folder of the workspace. path = "workspace:regional_dem_aber.tif" in [[data.dem.sources]] reads data/dem/regional_dem_aber.tif, and path = "workspace:." in [[data.hydrometry.sources]] reads the station folder data/hydrometry/. The folder is the role of the key, and the parameter reference gives it on the card of each key that accepts the form. A relative path still reads from the project root. The frozen config.toml, config.resolved.toml and the inputs of manifest.json write every file of data/<role>/ in that form, and they follow the data folder that [workspace] gives.

  • when = "session" draws a figure when a calibration session ends, into sessions/<s>/figures/. when = "after:extract", "after:derive" and "after:export" draw during the run into runs/<run>/figures/. hmp.show(ref, what="figure", name=...) draws a variable or a preset on a run, a session or a set of runs.

  • A figure is asked by the name of a variable: run.figure("recharge"), run.figure("recharge", type="series", station="zone:catchment", cumulative=True). [[display.figure]] draws figures at the end of a run, and [display.presets.NAME] names a request of your own. run.figure(..., data=True) and hmp show --figure NAME --data DIR give the tables behind the figure, and --engine names the engine.

  • The variable travel_time_to_exit maps the time the water of each cell takes to reach the end of its pathline, in years, for a run that tracked particles. Each recorded position of a pathline gives a sample, a cell takes the mean of its samples, and a cell no pathline crosses is interpolated from its neighbours. With backward tracking the value is the age of the water. Draw it with run.figure("travel_time_to_exit", overlays=["outline", "network", "seepage", "pathlines"]). The pathlines overlay draws 250 lines at most. The particle_tracks figure takes variable: it then draws the map of that variable under thin dark lines, as in preset = "particle_tracks", variable = "travel_time_to_exit", and a figure drawn by a Python function receives variable when its signature declares it.

  • A section of a water table fills the saturated zone and the unsaturated zone, draws the land surface and the water table as one thick step per cell crossed, on any mesh, and frames them closely when the aquifer is deep. It marks the seepage cells of its period on the land surface, and its title gives the period, the way the line runs and the vertical exaggeration. A section is drawn flatter than a map. The overlays seepage and pathlines draw the seepage cells and the particle paths over any map, and lake, wells and seepage follow the time of the panel. The particle_tracks figure draws the seepage and pumping cells where the paths end, takes time, and colours each line along its way by the age of the water, from its release to where it leaves the aquifer. The lines released outside the catchment are thin and grey, and beyond 350 lines of a kind one in n is drawn. A log colour bar that spans more than two decades labels its decades only.

  • A site file placed on top of a shared calibration file names its own case. The case of a calibration is now named by the first [simulation] name met from the file that is run down to the file that writes [calibration]. Before, only the file that writes [calibration] could name it, so several site files on one shared calibration all took the same case and piled up as .v2, .v3.

  • A calibration on the stream network reads back in full. hmp show on its session writes the value of each parameter at the best trial of the phase that moved it, with its unit, and names the calibrated variable network where it said discharge. The session report draws network_agreement and downslope_distance for the best run. The page of a promoted run gives its calibration cost, and run.table("calibration") or hmp show RUN --table calibration lists the parts of that cost, such as the two distances. A map of network_agreement, downslope_distance or simulated_active_network that lists no overlay leaves the mapped reaches off, because they covered the cells.

  • A run on Windows no longer stops with HMPY.E000 and a bad file descriptor when it writes a durable JSON document such as outcome.json. The write flushed the staged file through a handle opened for reading, which Windows refuses. The handle is now opened for writing.

  • hmp run on a calibration file draws the figures its [display] asks with when = "session", such as root_search. Only hmp calibrate drew them, so the same file gave fewer figures by hmp run, with no warning.

  • The bdtopage source downloads again. The Sandre service stopped serving the GeoPackage pages the source asked for, so every box that was not in the cache failed. The pages are now asked as GeoJSON, which gives the same reaches, geometry and values, and a page that is not in Lambert-93 is refused.

  • A run exports the tracks of its particles as the vector layer pathlines: one line per particle that moved, with its travel time in years (travel_yr), as a GeoPackage or a Shapefile. [[export]] variables = "pathlines", run.export("pathlines") and hmp export <run> pathlines write it.

  • lab.read("head") reads a variable of the solve of a lab, before any run is written: the water table of every cell, the discharge of the catchment, the saturated thickness and the release per cell. It solves first when the model is stale. The solvers answer head on every cell for it, through the port a calibration trial reads, on MODFLOW 6 and MODFLOW-NWT.

  • At the Python prompt, the objects of a lab and of a run print a short summary and no longer their arrays: lab.state, its mesh, model, properties, geometry, flow, domain, catchment and configuration, and run.mesh. A mesh says how many cells it has, its area and its extent, whether its cells form a regular grid and where its arrays are. The mesh of a lab and the mesh of a run answer the same calls: n_cells, cell_centers(), cell_areas() and structured_shape.

  • A map and a section take limits = [low, high], the colour limits in the unit drawn. Values beyond take the end colours, and the colour bar is pointed on that side. A map takes line, the trace of a section, and draws it dashed. A water-table depth map uses a pale jet, blue for a shallow water table and red for a deep one. The seepage overlay fills its cells in black, and the pathlines overlay draws every line up to 2000.

  • A variable can now be drawn as a section, against another variable, as a distribution or by group, with type=: run.figure("head", type="section") cuts the layers along a line from the outlet, run.figure("topography", type="xy", variable=["topography", "watertable_depth"]) plots two fields cell by cell, run.figure("discharge", type="distribution", station="GAUGE", cumulative=True, observed=True) gives the flow duration curve, run.figure("budget", type="groups", station="zone:catchment", reduce="mean") draws the mean budget as bars, and run.figure("discharge", type="groups", by="month", station="GAUGE", observed=True) draws the monthly regime as boxes. Use a station of your run in place of GAUGE.

  • The interactive engine draws the frames map, series and volume as an HTML file that loads plotly.js from a CDN, up to 100 000 cells. Try run.figure("watertable_depth", engine="interactive", save="depth.html") or hmp show RUN --figure watertable_depth --engine interactive --to depth.html.

  • The frame volume draws the block of a variable in 3D, with type="volume". It has the interactive engine only.

  • Five derived cell fields are variables like the others: simulated_active_network, network_agreement, downslope_distance, depression_fill_depth and package_cells. run.figure("package_cells", reduce="max") maps the boundary package that acts in each cell, and run.figure("simulated_active_network", type="series", station="zone:catchment") gives the share of the catchment that flows. type="table" prints the simulation.* columns with their labels, and against="<run name>" on a map draws the difference to another run of the project.

  • run.figure("simulated_active_network") now draws the map of the variable of that name, which is what a name that both paths know does. Its old options are refused with the list of panel fields. network_agreement and downslope_distance follow the comparison the run scores (seepage and closure, no visible flow), so they give the counts of seepage_network_confusion_map, while simulated_active_network keeps the visible flow of the sealed output. A trials panel never mixes two phases, takes the cost label of its phase and says how many trials it shows out of how many the session ran.

  • Five presets and twelve special figures are drawn by name. The presets are hydrograph, residuals, water_budget, watershed_id_card and network_expansion, and a preset has holes you fill with the panel fields it lists: run.figure("hydrograph", variable="stage", station="lake:1") or hmp show RUN --figure hydrograph --opt station=NANCON. v2.0.0a5 - 2026-10-13#

This alpha adds a daily soil reservoir for the recharge, a new way to draw the observed network from its heads, and a computational top for MODFLOW 6. It also removes the burn of the mapped network into the DEM and fixes many Boussinesq and validation errors.

Added#

  • [flow.sinks_sources.recharge.soil] computes the recharge from a daily soil reservoir fed by the rain and the ETP, instead of the SIM2 drainage. It works with MODFLOW 6 only. Main keys: ru (required, calibratable as soil.ru), alpha, kc, impervious_fraction, bypass_fraction, transit_time, spinup.

  • hmp run <file> --until load_data checks the soil alone. It prints the budget in mm/year and the recharge for ru from 50 to 250 mm, and writes no run. The section refuses what would count water twice and says what to write instead.

Each trial publishes n_heads, n_heads_lost, head_snap_p90_m and heads_trace_near_map_share. The figure observed_network_heads_map shows the result.

Added#

  • Added MT3D-USGS support with new Mt3dms, Masstransfer, and watershed.transport modules, included Example 09, and provided executables for Linux, macOS, and Windows.

  • Added the GR4J rainfall-runoff calibration toolbox with scripts, figures, and sample data under src/modeling/gr4j.

  • Added the PyHELP land-surface coupling (API, CLI, preprocessing) together with Example 10 resources and a Windows-only environment file.

  • Added Example 11 to run the full workflow from scratch without plots.

  • Added the test/01_test_non-regression suite and reference outputs for regression testing.

  • Added yearly intermittency plus MT3D seepage concentration and accumulated mass to the timeseries exports.

  • Added platform-specific conda environment files for HydroModPy 0.1.

Changed#

  • Updated modflow.py to support elevation-driven decay parameters, optional EVT extinction depth, and creation of the LMT link file when using MT3DMS.

  • Updated the hydraulic configuration so it keeps the new decay settings and exdp value.

  • Updated modpath.py particle seeding to center start points, respect model_folder, and align forward and backward runs.

  • Expanded the watershed_root workflow with transport functions, a calibration results folder, MT3DMS helper modules, and the PyHELP preprocessing function.

  • Improved timeseries handling so recharge and runoff accept scalars, series, or dicts while exposing the new MT3D metrics.

  • Updated geographic and hydrography helpers to fall back on existing DEM rasters and clip optional stream inputs.

Fixed#

  • SIM2 climate ingestion now uses the current Météo-France variable names and units and exposes the soil drought index.
