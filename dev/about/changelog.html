Changelog#

Every release of HydroModPy and every change since the last one, newest first. The page is the CHANGELOG.md file at the root of the repository, included as it is. It follows Keep a Changelog and Semantic Versioning. Under each release, Added lists new features, Changed lists changes of behaviour, Removed lists what was deleted and Fixed lists bug fixes.

The [Unreleased] section is the work merged since the last release. It ships with the next version.

The keys added, removed or changed in the TOML file between two versions are listed, from the models, in What changed in the TOML. For what a version number promises, see Versions and stability.

Unreleased#

Changed#

  • MODFLOW-NWT defaults to options = "MODERATE". Under chi-MD, the default linear solver since 2.0.0a5, "COMPLEX" runs BiCGSTAB on a level-15 incomplete factorization: on the ten-layer example 12 regression model it diverged at the first solve and NWT stopped on a core dump. "MODERATE" (Orthomin, level 1) converges in 60 outer iterations at most, every budget within 0.08 %, where the former GMRES default left -148 % and +91 % in two periods. The Brutsaert recession case gives the same metrics under both presets, and the NWT validation profile keeps "COMPLEX". On the fast example 12 regression the outputs move by 0.02 % (0.12 % on one percentile), the mean water-table depth by 0.9 mm.

Fixed#

  • A resume of a killed run (hmp run --resume) works in the scratch folder of the run it continues, instead of letting the sweep of killed runs delete it: the delineation and the mesh are reused, not generated again. A <run>.holder file keeps the sweep of other runs away while the resume runs.

  • On Windows, the scratch folders of killed runs are swept too. Liveness is read from the process exit code; os.kill(pid, 0) is not used there.

  • bootstrap_proj(), run by every hmp command, no longer points PROJ_DATA at the database of pyproj when a bundled rasterio, pyogrio or fiona ships a newer one. On Windows with Python 3.11 (pyproj 3.7.2, rasterio 1.4.4) every rasterio CRS lookup after the bootstrap failed with “DATABASE.LAYOUT.VERSION.MINOR = 4 whereas a number >= 5 is expected”, in the process and in its workers.

  • Export plans and the step 0 refusal of two [[export]] blocks writing one file name the files with forward slashes on every OS, as the TOML spells them. Windows printed backslashes.

  • On Windows, hmp run and hmp calibrate --list-phases print the paths under the working directory with forward slashes; a broken catalog index error names the file as it is spelled on disk; a file:///C:/... input of a capability job resolves to that file instead of a path under the job directory.

  • Example files check out with LF line endings on Windows too, so their size and sha256 match the example catalog.

  • A console log line no longer fails with “— Logging error —” when the stderr stream its handler was opened on has been closed since.

  • On Python 3.11, a solver adapter whose metaclass answers every attribute is refused, as on 3.12 and later: the members are read statically.

  • The page check of the docs no longer reports valid {doc} links as dead on Windows.

  • The example 12 regression goldens follow the code. Both extensive cases read buff_area = "20%" as 20 % more area since 2.0.0a4, so their domain went from 6 468 to 4 148 cells; the accumulation flux sums the descent D since 2.0.0a5; the NWT case now converges. MODFLOW 6 and MODFLOW-NWT agree on the new domain: mean head 122.686 against 122.685 m, drain outflow 0.06307 against 0.06305 m3/s, where the GMRES golden stood 0.5 m below MODFLOW 6.

[v2.0.0a5] - 2026-10-13#

Added#

  • [geographic.catchment].dem_resolution: the cell size the DEM is aggregated to before anything is delineated, a length such as "75 m". The routing surface, the catchment, the mesh and the model top all take it; unset keeps the pixel of the DEM file. Each coarse cell is the mean of the fine pixels it covers, on a grid aligned on the upper-left corner of the DEM, and a value finer than the DEM’s own pixel is refused when the run starts. It is how a 25 m BD ALTI download runs at the 75 m of the published examples.

  • flow.partition_release_depth_m: the depth scale, in metres, over which the regularized partition of the Boussinesq solver starts to release water at the surface, 0.05 m by default.

  • Validation case stream_depletion_glover_balmer_2d: a well pumping 100 m from a stream held on the west side, against the Glover and Balmer (1954) stream depletion and the image-well Theis drawdown, on the six solver variants; the depletion is read from the per-cell constant-head budget.

  • Validation case hantush_recharge_mound_2d: the growth of a groundwater mound under a rectangle of recharge read from a raster, against Hantush (1967) linearized with the mean saturated thickness, on the six solver variants, with a plan-view error map. Its two Gmsh meshes keep every cell wholly inside or outside the rectangle, since a mesh cell takes the recharge pixel under its centroid.

  • Validation case linearized_unconfined_boundary_periodic_1d: a daily tide read as hourly means on a side head, against Ferris (1951), with the decay and lag lengths of the Ferris method, on the six solver variants.

  • Validation variants modflow6_voronoi (the default dual of a Gmsh mesh) and boussinesq_local (the default Boussinesq engine, no PETSc), a patch test of uniform flow on skewed triangles, a grid-convergence test on the production path, and the data-rich transient twin (K and Sy from heads and discharge) again.

  • The Validation page draws, per case, the plan-view error of the 2D cases with their meshes, the space-time error of the transient 1D cases and the samples of each calibration method against the truth. It compares MODFLOW 6 and MODFLOW-NWT on example 04 from runs stored at full precision.

  • observed_rasterization = "heads" on a network calibration output draws the mapped network from its heads only. The free ends of the map are found by geometry, whatever the source; an end is a head when the largest drained area within the snap radius does not exceed the same window at the other end of its reach. Each head lands on the nearest cell draining at least heads_min_drained_area_km2 (0.02) within heads_snap_radius (100 m), and the criterion’s own descent draws the rest down to the outlet. The map is connected by construction, so the path a field, a ditch or a rectified reach gave the mapped line no longer counts as model error. A minimal map is traced from its own heads, the maximal one from both sets. Each trial publishes n_heads, n_heads_lost, head_snap_p90_m and heads_trace_near_map_share. On the Flume Voronoi run: 112 heads, 1 lost, one piece of 5078 cells to the outlet, 99.5 % of it within 100 m of BD Topage, where "crossing" left 1989 pieces.

  • The figure observed_network_heads_map draws the mapped lines, the traced cells, each head with the cell it landed on, and the lost heads, with the settings the run was scored with.

  • The dam foot of a lake whose spillway is declared (an outlet of the lake package releasing downstream) is a forced head of the heads rule: the criterion draws the reach below the dam from it even where the descent of the heads above leaves the reservoir through a lower saddle. It comes from the model, never from the observed map, is counted apart (n_forced_heads), never makes a map draw that the rule refuses, and a lake without a declared spillway has none. It is stored with D as mesh/descent_dam_foot, read alone by the redraw of a stored run, and marked on observed_network_heads_map. On the Cheze the descent already leaves the reservoir by its dam, and nothing changes.

  • The recharge can come from a daily soil reservoir fed by the rain and the ETP instead of a drainage loaded from SIM2: [flow.sinks_sources.recharge.soil], MODFLOW 6 only, with ru (the available water capacity in mm, required, calibrated as soil.ru), alpha (0.6), kc (1.0), impervious_fraction (0), bypass_fraction (0), transit_time (0, at most 30 days) and spinup ("first_year" or "none"). Each SAFRAN cell is a threshold bucket in float64 (the rain before the ETR, the ETR reduced below alpha x ru, the water above ru to the water table) whose balance closes to 1e-16 of the rain. Every run and every calibration trial computes it again; the recharge reaches RCHA as one gridded record, and with "etp" in flow.active_sinks_sources the ETP the soil left unmet is offered to a new EVTA whose surface is the drain elevation. hmp run <file> --until load_data checks the soil alone: it prints the budget in mm/year, the recharge for ru from 50 to 250 mm and the gauged discharge, and writes no run. A run keeps the daily columns under fields.zarr/forcing/soil/ and the yearly budget in tables.parquet/soil_budget.parquet. The section refuses what would count water twice ([data.recharge], [data.runoff]), another solver, a lake without its stream network and a steady first period, each refusal saying what to write instead. On the Nancon, daily 2015-2020 with K and Sy unchanged, the KGE of the gauged discharge goes from 0.65 with the SIM2 drainage to 0.79 with the soil (ru = 150 mm), and a grid calibration of K and Sy finds K inside its range (3.2e-5 m/s, NSE on log flows 0.84) where the SIM2 drainage keeps it on the 1e-7 m/s bound (0.74). The mean yearly recharge of the soil stays within 3 % of the SIM2 drainage plus runoff over 1985-2015 and 2015-2020, with no summer floor: the SIM2 drainage keeps about 0.3 mm/day all summer from 2016 on only.

  • [data.soil_capacity]: a raster of soil water capacity in mm spreads ru over ten classes inside each SAFRAN cell; the recharge is computed per class and weighted back, never on the mean capacity of the cell.

  • source = "explore2" for [data.precipitation] and [data.etp] reads a local DRIAS Explore2 NetCDF: cut by the run box in its Lambert II extended grid before any value is read, converted from kg m-2 s-1 to mm/day, resampled onto an 8 km grid in EPSG:2154, read again at each run; a calendar other than the standard ones is refused.

  • Example 04 gains step6_soil_reservoir.toml, the sixth step of the staircase.

  • method = "lhs": a stratified Latin hypercube over the transformed parameter space (scipy.stats.qmc.LatinHypercube), sized by method_options.n_samples, with optimization = "random-cd" to spread the points further. max_iter = "auto" budgets exactly n_samples, and a smaller written max_iter is refused at load instead of cutting the design. The initial sample of gp_mapping is now described as what it is, an independent draw per parameter, not a Latin hypercube.

  • [flow.sinks_sources.etp] extinction_depth is calibratable, as [calibration.parameters.extinction_depth] with its bounds in m: each trial rebuilds the EVT of MODFLOW 6 in soil mode, and of MODFLOW-NWT, with its own depth.

  • [calibration] persist_trial_series = true writes the simulated and observed series of every point output a completed trial scored, as sessions/<name>/trial_series/trial-NNNNNN.parquet, without promoting the run; hydromodpy.results.session_journal.read_trial_series reads them back. Off by default.

  • [flow.sinks_sources.recharge.soil] impervious_fraction is calibratable, as [calibration.parameters.impervious_fraction] with bounds below 1: each trial recomputes the runoff of the sealed share and adds it once to the discharge it scores.

  • [flow.sinks_sources.recharge.soil] curve_number adds a curve-number runoff in the manner of HELP (Schroeder et al. 1994): its retention moves between the dry (CN1) and wet (CN3) values with the soil water, so ordinary rain on a dry summer soil does not run off and rain on a wet winter soil does; runoff_time (1 day) routes it through a linear reservoir to the gauged discharge. Both are calibratable; off by default, results unchanged.

  • runoff_lag (0 day by default, at most 5) holds the routed curve-number runoff back by a fixed travel time, after runoff_time and before it joins the discharge, with fractional days interpolated between whole-day shifts; calibratable as [calibration.parameters.runoff_lag]. The first days of a run borrow from the settled spin-up instead of reading as zero when spinup = "first_year". In an offline test on the Flume catchment, delaying the routed runoff by 0.75 day raised the daily NSE from 0.66 to 0.78, with the same optimum on the calibration period and on an independent one.

  • The exponential vertical profile of a field is calibratable: [calibration.parameters."K.characteristic_depth"] (and min_factor) tune how K or Sy decrease with depth, evaluated at the layer centres. A calibration target that is not the headline quantity of its instance now takes its physical bounds from its own leaf, so a depth under K is no longer checked against the range of a conductivity.

  • [geographic] dem_correc_type = "capped_breach", with [geographic.capped_breach] max_depth (0.5 m) and max_distance (200 m), conditions the routing DEM by a least-cost breach bounded in metres, then fills what the breach left (Lindsay 2016). The two bounds become Whitebox’s max_cost, a cumulative lowering along one breach path, and max_dist, counted in cells. The realised lowering is measured, logged and stored with the geographic metadata, with a warning when it exceeds max_depth. It is an option and fill stays the default: against fill, the catchment moved by less than 0.1 % on the Flume (25 m) and on the Nancon, but the agreement with BD Topage moved by 1.74 points on example 04’s 75 m DEM and by 1.22 points on the 25 m Nancon DEM, over the one-point gate set for a default change (0.22 point on the Flume).

  • [data.crossings] gathers where a stream may meet a structure: the roads and railways of the BD TOPO (source = "bdtopo", Geoplateforme WFS; a segment above the ground is a bridge), the obstacles of the ROE (source = "roe", Sandre WFS; dams, weirs, and bridge sills kept as weirs) or a vector file with a kind column (custom). These are structure data, an input of the model, never a calibration target.

  • The ground G: the DEM plus the declared corrections, read by the routing DEM and by the model top in both geographic entry points. [geographic.crossings] (off by default) notches each road, railway or bridge crossing of the generated river network: the embankment span on the channel is lowered to the bed interpolated between the ends read bed_reach (50 m) upstream and downstream, across notch_width (10 m), by at most max_depth (3 m), and never where a dam or a weir is declared. On the Flume: 231 crossings found, 127 notched, 330 pixels lowered (median 0.32 m), catchment area and agreement with BD Topage unchanged.

  • [geographic.bed_regularization] (off by default) regularises the channel bed in the model top. On the pixels of the generated river network A, the ground G is replaced by its least-squares isotonic fit along the channel tree (Pardalos and Xue 1999): the bed never rises downstream and keeps its mean. A crossing notched by [geographic.crossings] is a gap the fit interpolates across, a weir or a dam of [data.crossings] within the crossings snap_radius cuts the tree, and a declared lake is left out with its surface. min_slope (1e-4) sets the least drop, centred on each flat. The fit runs on the full-extent G, written as dem_ground_bed.tif, and serves both the model top and the SFR streambed, so DRN and SFR read one bed; the routing DEM, A, the catchment and the mesh never read it, and the mesh cache key ignores the section. dem_ground_bed.json reports the rises before the fit, the pixels raised and lowered, the blocks pooled at confluences with their amplitudes and what the closing pass raised. With the fit on, [geographic.crossings] path is resolved from [[data.crossings.sources]] even with the notch off, so declared weirs and dams cut it. The notch writes its own footprint (dem_ground_notch_footprint.tif), the gaps of the fit. Enabling the fit by default is left open.

  • [[data.dem.sources]] source = "ign_geoplateforme_dem" takes dataset = "rge-alti": the RGE ALTI is assembled from the Geoplateforme WMS-Raster service by extent, at 5 m (default) or 1 m, in tiles of at most 2,500 pixels (the server stops at 5,010). Inland, at 5 m the server returns the 1 m pixel holding each centre, unchanged; other sizes go through an undocumented kernel and are refused. The server nodata, the flat -5 m water and the blend around them are nodata, while real land below the sea level is kept (the Ferques quarry, -66 m). The share of the box outside France, filled by another source, is written in the sidecar and warned above 1 %. A request above 150 million pixels is refused with its size, and 1 m is refused on the project bootstrap box (60 km), before any request. Against the BD ALTI averaged at 25 m: bias -0.03 m, standard deviation 0.41 m. On the Flume box at 5 m: 2,000 x 2,000 pixels in 7 s cold.

  • [modflow6.sgrid.top_sampling] mode = "zonal" also samples the top of a structured grid coarser than its DEM (planar.mode = "resample_to_shape"): a cell holding pixels of the generated river network A takes their channel_stat (lowest pixel), the other cells their hillslope_stat (median), as on a Voronoi mesh; the bottom and the idomain keep their rule, and keep_native and centroid are unchanged. On the Flume at 75 m the channel cells sit 0.90 m lower than the resampled top (median; 2.98 m at the 90th percentile of the absolute gap), the hillslope cells unchanged in median.

  • hmp config resolve FILE prints the TOML a base_config chain resolves to, before validation.

  • Merge directive key__merge = [...]: merges a list of tables with the inherited one, table by table, and refuses another length, a missing inherited list, items that are not tables, or the plain key written beside it.

  • hmp.run(path, name=...) names a run from a TOML path. Any other keyword on a path raises a TypeError that says to pass a configuration object.

  • hmp.read(run, field, time=...) and Catalog.read take a date, "first", "last" or a numpy integer; a date reads the stress period that holds it. Another kind of time raises TypeError, a time on a series or a feature raises ValueError.

  • hydromodpy.core.env lists every HMP_* environment variable HydroModPy reads, with its default, scope and description. tests/unit/architecture/test_env_vars_are_registered.py fails on a variable without a row or a row nothing reads.

It accepts base_config, the __append, __delete and __merge forms, quantities written as text with a unit, bare dates, and files that omit required keys. Changed#

  • With the whole per-cell budget kept, [[export]] variables = "all" and hmp export --list offer every budget term and every field rebuilt from it (outflow_drain, release_flux, the accumulation fluxes, simulated_active_network, the storage terms), a portable .hmp package carries the budget group, and the testbed tables of a MODFLOW run gain outflow_drain_* and accumulation_flux_* columns. Left as they were, and not covered by this change: the legacy solver post-processing that carries the same field names without a caller (modflow_common/options.py, modflow6/postprocess/, nwt/_post_processing.py, mt3dms.py), the float64 boussinesq_state histories that duplicate budget/, the testbed reader of recharge_flux and the comparison series mapped to seepage_areas (names no store holds), and the Boussinesq adapter that declares release_flux for a calibration and refuses it at extraction.

  • The example projects, the regression fixtures and the validation cases no longer declare [simulation.results.derived] or [simulation.results.budget]: they keep the whole per-cell budget by default, and example 11 says a run without figures has nothing to declare.

  • A calibration that saves runs (save_runs = "best_n" or "all") writes the best run with the results options of the project file, and every other saved run with keep_per_cell_budget = false: those keep only the per-cell terms their figures, exports, calibration outputs and observation points read.

  • A figure, a map overlay or a reader skipped because the run did not keep a per-cell budget term now says which terms the run kept, which ones the field needs and that [simulation.results] keep_per_cell_budget = true (the default) keeps them; a run that kept every term the solver produced and has no drain, stream, lake or surface excess is still told the model has no such exit. The geometric seepage fallback of a surface-excess solver names the run’s policy the same way. hmp viz and the calibration loader read a sealed runs/<name>/config.toml through the stored migration.

  • A run keeps its whole per-cell budget by default: every scalar term the solver produces, storage included (storage under MODFLOW-NWT, storage_ss and storage_sy under MODFLOW 6), is written under budget/ at extraction, and the group says what it kept (attributes policy and kept_terms, repeated in manifest.json). The developer option [simulation.results] keep_per_cell_budget = false keeps only the terms the run’s own consumers read: the figures of [display].figures with their optional fields and overlays, the [[export]] names, the declared calibration outputs, the [observation] points and the seepage mask of a surface-excess solver. The filter acts before the per-cell slab is built, so nothing is computed to be dropped; the intermediate budget the seal dropped, and its log line, are gone. A field whose terms the run kept only in part is refused, never served as a partial sum, and the message names the terms the run kept and keep_per_cell_budget. On the six-year daily Nançon run (21 406 cells) the group weighs 299 MB, 3.7 times the head; writing it costs no more extraction time than before.

  • Boussinesq stores the descent of a raster run: the Whitebox D8 pointer of the filled top becomes mesh/descent_* once per run, and the accumulation fluxes route on it at read. A run on a triangle mesh stores none, and its accumulation fluxes are unavailable instead of the unrouted local outflow written under that name before. Boussinesq no longer writes derived/seepage_mask nor derived/seepage_rate: the mask is rebuilt from budget/surface_excess, and seepage_rate leaves the field registry.

  • The catchment discharge and well pumping series read the catchment row of the budget table when the run has one (MODFLOW 6), the per-cell field masked to the basin otherwise. A Boussinesq run, which now keeps its per-cell budget, gets the basin total instead of the total of its whole domain.

  • MODFLOW-NWT STREAM LEAKAGE and LAKE SEEPAGE records are stored as stream and lake, the names their MODFLOW 6 counterparts take, and enter release_flux.

  • A file or a stored run configuration that writes [simulation.results.derived] or [simulation.results.budget], at the root, in a comparison or testbed overlay or in the dotted overrides of a calibration phase, loads with both tables dropped, whatever they held, and says so in one line; hmp doctor --fix-config removes them from the file. A sealed run configuration is migrated by the stored route only. The new developer key [simulation.results] keep_per_cell_budget, true by default, takes their place.

  • Every derived field of a run is rebuilt on read, over a range in bounded passes: the water table, its depth, the seepage mask, the drain outflow, the two accumulation fluxes and the solute seepage chain (concentration_seepage, mass_seepage, mass_accumulated), as release_flux already was. A step read alone is the row of the range read, and the values equal, bit for bit, what the post-run derivation wrote. The seepage mask of a six-year daily run on 21 406 cells reads in 0.3 s instead of 9.4 s. The first transient period never got ATS at all.

  • Adaptive time stepping no longer discards the requested sub-stepping. MF6 ignores the TDIS NSTP of a period ATS covers, and the record declared dt0 = dtmax = perlen, so a run asking for ten steps per period got one: 0.0481 m of RMSE against the erfc closed form instead of 0.0035 m. Both bounds are now the step simulation.time.substeps_per_period asked for, so ATS can only cut below it, which is the failure recovery it exists for.

  • hmp doctor --fix-config reads a config carrying a byte-order mark. tomlkit parsed the BOM as an empty key on line 1, so the whole fix aborted and nine validation configs in this repository could not be migrated at all.

  • Two example report builders read firstpersteady from a solver tgrid section that never held it, and the Nancon sweep script wrote it into the configs it generates, producing files the runtime refuses. All three now use [flow].first_period_steady.

  • MODPATH pathline and endpoint times are now converted to the unit the particles group declares. The MODFLOW-NWT extractor stored raw model time, seconds, while labelling it days, so every stored travel time and every residence-time figure built from it was off by a factor 86400.

  • ITMUNI is now read from the first non-comment record of a MODFLOW DIS file, where it actually sits. The previous reader parsed the LAYCBD line below it and always fell through to its default, so a MODFLOW-NWT run declaring anything but seconds had its calibration fluxes left unscaled.

  • The MODFLOW 6 PRT readers no longer fall back to DAYS when a run declares no time unit. An undeclared unit now means SIMULATION_TIME_UNIT, the unit the launcher builds every run in.

Removed#

  • DomainGeographicContext.river_mesh_trace and the direct CatchmentDelineation.river_mesh_trace runtime attribute were removed. Mesh river constraints now read GeographicDerivedFeatures.rivers.river_mesh_trace or an explicit river_trace; the in-memory mesh config source is now rivers.source = "geographic_features" instead of "domain_geographic".

  • Generic testbed input spellings [[testbed.variant]], [[testbed.variant_from_catalog]], TestbedConfig(variants=...), and TestbedConfig(catalog_variants=...) are no longer supported. Use [[testbed.case]], [[testbed.case_from_catalog]], TestbedConfig(case=...), and TestbedConfig(case_from_catalog=...).

  • Generic testbed outputs no longer write the legacy compatibility keys variant_id, variant_label, variant_count, or variant_from_catalog. Read case_id, case_label, case_count, and case_from_catalog instead.

  • Removed the application-level config compatibility aliases under hydromodpy.core. Use hydromodpy.config.HydroModPyConfig and hydromodpy.config.schema_export instead.

Fixed#

  • The PyHELP NetCDF export is now readable by the data layer it feeds. Its recharge variable was named rechg, which no data family looks up; it is now recharge. It also declared no CF grid mapping on its fields and no nodata attribute that survives decoding, so the file was refused on load.

  • A custom gridded source handed the whole NetCDF downstream instead of the variable it names, and the discretization then picked a variable out of it by taking the first one. On any CF file that is the scalar grid-mapping variable; on a multi-field export it could be any field. A source now carries only the variable it declares, and the picker skips grid mappings and dimensionless variables.

Changed#

  • Simulation identity keys renamed. [simulation].run_id and [simulation].on_collision are removed and now hard-fail under extra="forbid". Use [simulation].name for the run identity and [simulation].if_exists for name-collision behaviour. if_exists defaults to version (mint the next stem.vN), replacing the old replace default; replace and fail remain available. hmp doctor --fix-config FILE.toml migrates old keys in place.

  • Unstructured MODFLOW 6 grids now build a Voronoi/PEBI dual by default (exact CVFD orthogonality, about half the cells, XT3D off). The new grid_dual field controls this; set grid_dual = "triangle" to restore the previous triangle DISV grid. Upgrading an existing unstructured MODFLOW 6 project changes its heads and budgets, and any calibration params_hash cache must be invalidated after the upgrade to avoid reusing stale objectives. MODFLOW-NWT (structured DIS) and Boussinesq are unaffected.

  • Raster / VTU / shapefile auto-export now defaults to the last timestep instead of the first. Set [export].times = "first" to keep the previous behaviour.

  • Documented the release policy for SemVer/PEP 440 versions, alpha/beta/rc pre-releases, the new main default line, the frozen archive-v1 branch, release branches, tags, and GitHub Releases.

  • Prepared the v2 line as 2.0.0a1 and updated project metadata, docs links, source links, and GitHub workflow branch filters from master to main.

  • Per-simulation timeseries, budgets, and mass_balance rows now live as Parquet files under simulations/<uuid>.parquet/ instead of DuckDB tables inside hydromodpy.duckdb. DuckDB views with the original table names keep the read surface unchanged - every SELECT ... FROM timeseries call keeps working. See docs/developers/parquet_lakehouse_architecture.md for the layout and docs/developers/parquet_lakehouse_concurrency.md for the retry and atomic-rename patterns.

  • SimulationCatalog now retries on duckdb.IOException at both connect time (connect_with_retry) and execute time (@with_lock_retry) on every write path. Short-lived cross-process lock contention resolves transparently instead of surfacing as an error.

  • hmp run <calibration.toml> now drives real MODFLOW simulations through the new trial primitive (no more analytical mock). Each trial runs in ExecutionRegistry.lightweight=True mode, skipping Zarr/Parquet writes. Only the top-N iterations (via save_runs = "best_n") get promoted to full simulations. See docs/developers/calibration_guide.md.

  • make_hot_simulator now returns (calibration_vector, raw_results) so callers can persist selected series post-calibration without re-running the solver. persist_calibration_result renamed to promote_trial.

Added#

  • Four figures join the registry, each one a view the legacy example suite drew by hand and nothing in v2 could reproduce: recession_power_law (the Brutsaert-Nieber log-log plane of -dQ/dt against Q, with the late-time Boussinesq 1904 law overlaid), residence_time_distribution (the travel-time density of tracked particles against the exponential law of a well-mixed store), mass_balance_error (the solver’s own closure error per timestep), and concentration_boxplot (the distribution of a solute over the domain, timestep by timestep).

  • MODFLOW 6 Lake (LAK) package support: model one or several lakes/reservoirs as advanced boundary conditions with stage, bathymetry abacus, and bed leakance, driven from the [flow] boundary configuration. LAK is a MODFLOW 6 backend capability.

  • Streamflow Routing (SFR) support on the MODFLOW 6 backend, including SFR-to-lake water movers (MVR) so routed streamflow can feed a LAK lake.

  • Horizontal flow barrier support, including a dam cutoff wall (HFB), to reduce flow across a mapped line such as a grouting curtain under a dam.

  • Lake bathymetry bed carving: a bathymetry raster can lower the MODFLOW 6 cell bottoms under a lake so the aquifer grid follows the reservoir bed.

  • Lake-level calibration: calibrate against an observed MODFLOW 6 LAK stage series (variable = "lake_level") in addition to discharge and head.

  • Top-level [export] configuration section promoting the raster / VTU / shapefile / time-series export toggles to a first-class config block.

  • New geographic domain_extent option (box, watershed_buff, watershed) to select the modelled domain surface, and a mesh lake_refinement block to refine cells around lakes and dams.

  • Calibration refactor - trial primitive plus step auto-invalidation:

    • hydromodpy.simulation.execution.trial with TrialContext, prepare_trials, run_trial_light, promote_trial.

    • hydromodpy.pipeline.dependencies.earliest_affected_step computes which pipeline step must re-run first from a set of override paths, using longest-prefix match on the new config_sections class var declared by each of the 12 pipeline steps.

    • hydromodpy.calibration.metrics.build_metric_extractor - RAM-only metric extractor for MODFLOW-NWT discharge (DRAIN budget aggregated) and head at observation cells.

    • ExecutionRegistry.lightweight flag gates Zarr / Parquet / catalog writes in steps 06 and 07.

    • ParamsHashCache preload from DuckDB at session start for cross-session trial deduplication.

  • hmp report <session_id> - generates a self-contained HTML report under <workspace>/reports/<session_id>/report.html embedding the calibration session metadata plus the six calibration figures.

  • Six calibration figures registered in the Display registry: calibration_convergence, calibration_trace, calibration_landscape, calibration_posterior, calibration_objective_surface, calibration_pairplot.

  • Analytical calibration cases ported under hydromodpy.calibration.cases: recession_brutsaert (Brutsaert 1D recession) and groundwater_1d (Dupuit 1D aquifer). Both ship with synthetic chronicle builders + a calibrate_<name>(method, ...) dispatcher that hooks into CalibrationEngine.

  • hydromodpy.calibration.diagnostics helpers (convergence_rate, parameter_correlation, iterations_to_dataframe).

  • User guide: docs/developers/calibration_guide.md (replaces the two refactor prompts under the same directory).

  • hmp doctor now reports the Parquet layout health (orphan directories, leftover legacy tables, per-sim Parquet counts).

  • Unit tests covering atomic Parquet writes, view semantics, and 8-worker concurrent writes (tests/unit/results/test_parquet_lakehouse.py).

  • ~130 new calibration tests across tests/unit/calibration/, tests/unit/test_calibration_cli.py, and tests/regression/fast/calibration/ (including the Brutsaert golden regression for four optimization methods).

Removed#

  • _default_evaluator (analytical mock) from the user-facing calibration path. Custom metrics are now supplied via the objective = "module.path:fn" escape hatch.

  • hmp migrate subcommand.

Fixed#

  • SimulationCatalog.write_* methods are now tolerant of the DuckDB single-writer lock through the new retry decorator, fixing a latent bug where hmp list running concurrently with hmp run could raise IOException.
