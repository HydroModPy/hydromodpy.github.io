Add a test#

The test tree under tests/ has one folder per family. This page tells you which family to pick, which marker to use, which fixture to reach for, and how to run the tests. The families themselves, and how to read a failure of each, are in Tests.

Pick the tier#

Tier

When to pick it

Limits

unit

One local function, class or schema in isolation.

Pure Python, no real I/O outside tmp_path. Timeout 60 s.

integration

Several layers compose, without a golden file.

May write to tmp_path. Timeout 300 s.

e2e

One full user scenario through hmp run, hmp export or hmp data add.

Reads back what was persisted. Timeout 1800 s.

regression

Detect drift in a known workflow output.

fast (a few minutes in total) and extensive (heavier fixtures). Timeout 300 s.

validation

Compare a numerical result with a trusted reference (analytical, MMS, calibration twin, solver sanity).

Tolerances live next to the case. Timeout 900 s.

characterization

What one real run leaves on disk, read with the formats a stranger would use.

Five strict xfail cases record claims the code does not honour yet.

contract

Several implementations of one port behave the same.

Parametrised over the implementations.

tests/conftest.py tags a test with its tier marker and a default timeout from its folder, so you do not write @pytest.mark.unit.

Markers#

pytest.ini declares every marker with its meaning and runs with --strict-markers: an undeclared marker is an error. The ones you will use most are regression, validation, analytical, steady, transient, fast, slow, extensive, nwt, mf6, petsc, boussinesq, solver_sanity, network, binary and allow_subprocess.

import pytest


@pytest.mark.regression
@pytest.mark.fast
@pytest.mark.mf6
def test_my_workflow(tmp_path): ...

hmp test selects subsets of three tiers:

hmp test unit
hmp test regression --fast --mf6
hmp test regression --extensive
hmp test validation --analytical --steady

The other tiers go through pytest (for example pytest tests/integration -q, pytest -m solver_sanity -q, pytest -m petsc -q).

Where to put the file#

Mirror the package under test:

tests/unit/<package>/test_<feature>.py
tests/integration/<area>/test_*.py
tests/regression/fast/test_*.py
tests/regression/extensive/test_*.py
tests/validation/analytical/{steady,transient}/...
tests/validation/numerical/{steady,transient}/...
tests/validation/mms/test_*.py
tests/validation/calibration/test_*.py

Reusable fixtures#

The top-level tests/conftest.py exposes:

  • tmp_workspace: a fresh workspace directory, rooted in tmp_path with the standard data/ and projects/ layout.

  • minimal_config: a ready-to-run HydroModPyConfig for the smallest case. Extend it with model_copy(update=...).

  • update_goldens: true when pytest runs with --update-goldens.

For a DuckDB and Zarr catalog seeded under tmp_path, use the tests._helpers.fixtures_catalog.simulation_catalog context manager. tests/_helpers/ also holds the doubles to use instead of a network call, a Whitebox run or a solver spawn.

Unit pattern#

tests/unit/physics/test_transport_process.py builds a process from a mapping and checks what it holds:

from hydromodpy.physics.transport.transport import Transport


def test_transport_mapping_config_populates_all_solver_parameter_blocks() -> None:
    transport = Transport({"modpath": {"parameters": {"track_dir": "backward"}}})
    assert transport.modpath.parameters["track_dir"] == "backward"

Integration pattern#

tests/integration/test_shared_fixtures.py shows the shared workspace fixture at work:

import hydromodpy as hmp


def test_tmp_workspace_is_openable_as_a_catalog(tmp_workspace):
    with hmp.open(tmp_workspace, create=True) as catalog:
        assert catalog.list_simulations().empty

Regression pattern#

A regression test runs a small workflow and compares its signature with a committed golden file. tests/regression/fast/test_simulation_regression_fast_mf6_regression.py is one line of arguments to a shared helper:

@pytest.mark.regression
@pytest.mark.fast
@pytest.mark.mf6
def test_simulation_regression_fast_mf6_regression(update_goldens) -> None:
    run_simulation_regression(
        test_file=__file__,
        config_name="run_fast_mf6.toml",
        golden_filename="simulation_regression_fast_mf6_npy_signatures.json",
        update_goldens=update_goldens,
        ...,
    )

The helpers are in tests/regression/golden_utils.py (snapshot_signature, load_golden_reference, write_golden_reference). Refresh a golden with pytest tests/regression/ --update-goldens and review the diff before you commit it. A golden that moved says the workflow changed, not that it became wrong.

Validation pattern#

A validation case lives in two trees:

  • the benchmark logic in validation_cases/<case>/ (run_case.py, comparison.py, metadata.toml, tolerances.toml);

  • the pytest entry in tests/validation/<family>/test_*.py, which imports the comparison function and asserts the metrics.

The split lets the same case run as an automated test or by hand, for a figure-first diagnosis (python -m validation_cases.run_cases).

Tolerances are never inline magic numbers. A case envelope lives in the case’s tolerances.toml and is read through comparison.tolerances. A single documented scalar from tests/TOLERANCES.md is read through tests/_helpers/tolerances.py::tol('<slug>'). tests/unit/architecture/test_tolerances_single_source.py is the drift guard.

When the test should check the external solver and not the HydroModPy launcher, mark it solver_sanity. That subset flags solver-binary drift independently of the orchestration.

Run the tests#

Run the folder of the area you touched, and the architecture gate. CI runs the whole suite.

python -m pytest tests/unit/physics -q
python -m pytest tests/unit/architecture -q

Parallel runs. pytest.ini already sets --dist=loadgroup, which keeps the tests that share an xdist_group on one worker. Keep it: --dist loadscope ignores the groups. On a workstation use -n 8 or fewer, never more workers than cores.

python -m pytest tests/unit -q -n 8 --dist loadgroup

CI uses -n 2.

Whitebox tests run in series. The native Whitebox binding dies, and takes the pytest worker with it, when several DEM workflows run in one long-lived process. tests/conftest.py puts the Whitebox-backed tests in one xdist group, and the CI steps that run a tier in parallel exclude them and run them in a serial step. Do the same when you run a tier locally: run the Whitebox files without -n. tests/unit/architecture/test_whitebox_tests_run_serially.py checks the workflows. Never run two pytest sessions on the same scratch root.

Scratch folder. Tests write to HMP_TEST_SCRATCH_ROOT, /tmp/hydromodpy_tests/ by default. When /tmp is a small memory-backed filesystem, or shared with other sessions, a full disk truncates raster files and the failure looks like a bug in your change. Point the variable at a disk before you suspect your diff:

export HMP_TEST_SCRATCH_ROOT=$HOME/.cache/hmp-test-scratch

Pitfalls#

  • A unit test must not reach the network. Mock at the HTTPClient level (core/io/http_client.py) or use a double from tests/_helpers/.

  • A validation test keeps its tolerances in the case tolerances.toml or in tests/TOLERANCES.md through tol('<slug>'). It does not hard-code a threshold.

  • Raise coverage by asserting a real behaviour or an invariant, never by adding a test to hit a line. Codecov gates the patch at 80 % and the project at auto; fail_under in pyproject.toml is not a CI gate.
