Architecture gates#

Built from the module docstrings of tests/unit/architecture/test_*.py and the YAML contracts beside them each time the site is built. Fix a wrong row there.

17 gate modules and 4 YAML contracts. Run them all with pytest tests/unit/architecture -q. The rule is the first paragraph of the module docstring; the checks are its test functions.

Gates#

Module

Rule

Contract

Checks
test_cli_boundary.py

Seal the CLI boundary.

-

  • Cli boundary sealed
test_data_source_port_stands_alone.py

The data-source package must not import a manager, a catalog or a workspace.

layer_matrix.yaml

  • The scanner sees the data source package

  • The port module itself imports only core

  • A source imports no manager no catalog no workspace

  • A builtin source module opens no forbidden door

  • Every provider import stays deferred

  • Importing the port pulls in no provider library
test_env_vars_are_registered.py

Every HMP_* environment variable the code names has a row in hydromodpy.core.env.

-

  • Every variable the code names has a row

  • Every row names a variable the code reads

  • Every exclusion is still written somewhere

  • A row is complete and unique

Enforce the machine-readable layer-matrix contract.

layer_matrix.yaml

  • Layer tolerances are not redundant

layer_matrix.yaml

test_package_layouts.py

Enforce the import rules inside the packages that carry a <package>_layout.yaml.

calibration_layout.yaml, layer_matrix.yaml

  • Every package with a layout is seen

  • The scanner sees the package

  • Every part has a row

  • A row names only rows above it

  • A part imports only what its row allows

  • Another layer imports only the public modules

  • A tolerated layer imports only its line

  • The public patterns name existing modules

  • The text path files exist

  • No module sits at the root of data

  • A variable never imports another variable

  • The data source registry names only its builtin sources

  • The calibration evaluator registry names only its builtin evaluators

  • Config reads the upper parts only inside its validators

  • Evaluation reads optim only for types

  • Preflight reads the other parts only inside its checks

  • Calibration reaches solver only through generic ports

  • The display registry names only the figures package
test_run_context_state_surface.py

What a solver adapter receives of the workflow runtime is what it reads.

-

  • The package reads only what the view declares

  • The view is built in one place

  • A run context refuses anything but the view

  • The gate sees every spelling of a read

  • The gate sees an aliased import of the view

  • The view carries no catalog handle
test_run_product_reaches_its_consumer.py

Who may reach the execution registries, and who receives a run’s product.

-

  • Only the named modules reach an execution registry

  • Every allowed reader still reads a registry

  • A run context carries what its run produced

  • A post solver context is built through the one path

  • The gate sees every spelling of a registry read

  • The gate sees every spelling of a hand built context
test_solver_private_attributes.py

A solver package does not read another one’s private surface.

-

  • A solver package reads only the private names it declares

  • The shared modflow helpers read no private backend name

  • The gate sees a dotted read and not only a getattr
test_step_payload_keys.py

A pipeline step declares the payload keys it reads and the ones it writes.

-

  • The steps package holds the twelve known steps

  • A step declares the payload keys it touches

  • Every step but the first reads the one key f8 removes

  • The gate sees every spelling of a read

  • The gate sees every spelling of a write

  • The gate counts no read that is not a payload read

  • The gate follows a helper the step calls

  • The gate follows a helper of a helper

  • The gate finds a step that declares nothing
test_storage_boundary.py

Storage-boundary checks for direct DuckDB access.

  • Data cache file connections use retry helper

  • Cli diagnostic duckdb connections are read only

  • Cli heartbeat queries use workflow events view
test_terrain_port_stands_alone.py

The terrain package must not import a sibling of spatial.

-

  • The scanner sees the terrain package

  • Terrain imports no sibling of spatial

  • Every declared exception is still taken

  • The whitebox backend import stays deferred
test_tolerances_single_source.py

Guard the single-source tolerance policy.

-

  • Every tol call resolves to one real row

  • Every inline row is referenced by a tol call

  • Dupuit fixed head doc agrees with case toml

  • Documented tolerance count matches the table
test_whitebox_tests_run_serially.py

The Whitebox-backed tests must stay outside xdist in CI.

  • Every whitebox group file still exists

  • No parallel step collects a whitebox test

  • What a parallel step ignores is run somewhere serially
test_workflow_context_members_have_a_reader.py

Every member of WorkflowContext is read through a receiver typed as one.

  • No module reads a workflow context reflexively

  • Every workflow context member has a reader
