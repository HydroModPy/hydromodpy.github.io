Package: core#

The kernel leaf of HydroModPy. Every other package may read core, and core reads no sibling package, not even under TYPE_CHECKING. It holds what several layers need and none should own: the base of every config model, units, the paths of a project and a workspace, run state, the I/O primitives, the typed exceptions and a few kernels that two layers must compute the same way, such as the sign of a budget flux and the digest of a block of values.

A sub-package answers one question, and scoring/ is the port of the goodness-of-fit metrics, with a README of its own. The modules at the root hold the words every layer shares, for example the step names of pipeline_steps.py, the hierarchy of exceptions.py and the version string.

Each exception carries one of sixteen Category values, set once on the class that owns it and inherited below. cli maps a category to its exit code, so a new exception needs no line in the command line. logging.py keeps the handlers that a run adds in one SinkRouter, so no handler is added to the process logger while a run writes its log.

Importing hydromodpy.core loads neither the configuration nor the data stack. A helper used by one layer stays in that layer, and it moves here when a second layer needs it and the layer matrix forbids the edge.

The page of the package in the developer docs lists the modules with the first line of their docstring and tells how the folders fit together.

Inside the package#

The layer rules are checked by tests/unit/architecture/, and the unit tests of a folder are in tests/unit/core/. core receives what it needs as an argument and never imports a higher layer.

Configuration. Every config class of every layer inherits HydroModelBase of config_kit/base.py, which sets extra="forbid" and validate_assignment=True, so the strictness is written once. profile.py and visible_when.py decide which field shows in which profile, and a field visibility rule goes there and in introspect.py. A shared constrained type goes to types.py. calibrable.py lives here so that model and calibration need not import each other. root.py holds RootConfig, the root model class with its two migrations. Every helper that reads sections or migrates a file receives it as its root argument, which is how core reaches the root config without importing config. A section that must be listed at the root is added to the root model, never to this folder. field_param/ is the schema of a field-parameter payload. It lives here because model/properties builds the field from it and model/flow_config.py embeds it in [flow.param.<id>].

toml_io is the path of a file into a document. The loader follows base_config, migrates through the RootConfig it receives, and error_locator.py points a Pydantic error at a line of the file. A new merge rule goes to merge.py or overrides.py, and a path key to paths.py.

Units and fields. A bare number is read in SI and a string such as "0.36 m/h" is converted, with Pint loaded only when needed. A new alias of a config type goes to units/types.py with its canonical unit, a new physical bound to physical_bounds.py and a new axis label to labels.py, so no figure writes one. In fields, a new nodata convention goes to nodata.py once, and a new way to store a field goes to precision.py with its error bound. budget fixes one sign for every solver, the one MODFLOW gives it: positive when water enters the aquifer, negative when it leaves. A drain or release key goes to the tuples of flux.py, and a derived field that needs a new term to the table behind budget_terms_for in terms.py.

Paths, names and the host. state/layout.py holds the names under .hmp/, runs/, sessions/, jobs/ and trash/, so a new folder name inside a project goes there with its *_dir_for helper. workspace/path_registry.py holds the canonical paths that runtime components share under a workspace, and the metadata of a workspace is workspace_toml.py. The workspace is resolved in four steps, from the [workspace] keys, then HMP_WORKSPACE, then the scaffold <workspace>/projects/<name>/, then the project folder itself. A random consumer asks RngManager of state/rng.py for its seed, and nothing seeds globally. A host name or the proof that a process died comes from state/host.py, never from socket.gethostname() or a pid test in the caller.

Files. A new file format is one module of io that writes through atomic_replace.py. A new stored document takes a schema id and a check through document_version.py. A hard link and a rename onto a reserved folder go through filesystem.py, and a DuckDB open through db_retry.py, never duckdb.connect. A package that installs files into a workspace, whether an example, a published run or an exported project, writes the same INSTALL.toml that payload/index.py reads and writes. The installer plans every placement before it writes one, so a new placement rule goes to payload/install.py.

The running process. A bound on what one call may reach or take is a member of Bounds in runtime/bounds.py, and the check that applies it stays with the owner of the download or the delivery. A new HMP_* variable is one entry of runtime/env.py, a new signal rule or a new reader of the stop flag goes to interrupts.py, and a new kind of timed block goes to MEASURE_KINDS. For progress, a new kind of line goes to console/progress.py with its event in ndjson.py, and a new consumer of the events reads the NDJSON instead of adding a second display. A new protocol between two layers is one module of contracts with the concrete class in the layer that owns it, and real code never goes there.

Sites and time. A new column of the site table goes to site/row.py, and a new site key to site/config.py, after a check that site_fingerprint still ignores what must not change the identity of a site. time/selection.py is the one resolver from a date to a period that figures and exports share, and time/window.py cuts a long run into windows.
