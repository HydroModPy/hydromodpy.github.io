Package: examples#

What hmp example stands on: the catalog of shipped examples, the cache their files are fetched into, and the generator that writes the catalog from a checkout. It is a leaf above core. The CLI and the Python API (example_list, example_show and example_add of hydromodpy/_api.py) import it. This file is the map of the package.

Parts#

part

answers

catalog.toml

which examples does this version ship, and which files does each need? It is generated, ships inside the wheel ([tool.setuptools.package-data] in pyproject.toml) and is read with no network, so hmp example list cannot promise what the installed version does not know

manifest.py

the dataclasses ExampleFile, ExampleStation and ExampleEntry, the reader load_catalog and find_entry, and render_catalog, the emitter that produces the exact bytes of catalog.toml. The emitter is written by hand rather than delegated to a TOML writer because a test compares the file byte for byte

blobs.py

the content-addressed cache and the download. ensure_blob returns the cached blob or fetches it, and verifies its sha256 in both cases. resolve_source gives the prefix every repository path is appended to

install.py

install_example: write one example into a scaffolded workspace. Authored files go under projects/<directory>/, data files under data/<variable>/, and station rows are merged into the shared station registry of the workspace

generate.py

the whitelist and the generator behind hmp dev examples manifest. It reads each project config through the run pipeline’s own load_toml_with_base_config, so a variant that only overrides station_ids inherits the source and path its parent declared, as it does at run time

Why a file cache and not an archive#

The payload of one example is dominated by one shared file. Of the 92 MiB that example 04 needs, examples/data/dem/DEM_armorican_massif.tif is 90 MiB. The unit that is cached is the file, not the example: a zip per example would ship the DEM again for each example, while a blob keyed by its sha256 is downloaded once and costs nothing to every later example that reads it.

Blobs live at <cache>/examples/blobs/<sha256[:2]>/<sha256>, under hydromodpy.core.state.paths.cache_dir (HMP_CACHE_HOME overrides it), beside the solver binaries hmp install-binaries caches.

Where a file comes from#

HMP_EXAMPLES_SOURCE, when set, replaces the whole prefix (https://raw.githubusercontent.com/HydroModPy/HydroModPy/<ref>), the ref included, so one code path serves a release tag, a file:// URL and a local checkout. Without it the prefix ends with the ref of hmp example add --ref, and the ref defaults to v<installed version>.

A sha256 that does not match the catalog is a hard failure: the offending blob is deleted, nothing reaches the workspace, and the error names the file and where the bytes came from.

An install leaves a destination alone when its content already matches the catalog. A destination that differs is a file somebody edited: it is kept and reported, and hmp example add --force overwrites it. A workspace must already exist (a data/ folder, made by hmp workspace init).

The whitelist has one entry#

examples/projects/ holds some thirty directories, most of them development or gallery projects. One of them, 04_streamflow_intermittence_in_transient, is maintained and verified end to end. A catalog of thirty with one that works is worse than a catalog of one, so WHITELIST in generate.py is explicit, and a project earns a line in it once it runs from a freshly scaffolded workspace.

Import rules#

examples imports only core (tests/unit/architecture/layer_matrix.yaml): an example is described by paths, sizes and hashes, never by a loaded configuration. The root facade imports it in _api.py and cli through cli/_workers/example.py. Nothing else imports it.

Where to add what#

  1. An example in the catalog. An ExampleSpec in WHITELIST (generate.py), once the project runs from a fresh workspace. Then hmp dev examples manifest rewrites catalog.toml; a unit test compares the regenerated bytes with the committed file, so a drift fails the suite.

  2. A change to the catalog format. manifest.py (reader and render_catalog together) and SCHEMA_VERSION.

  3. A change to how files are fetched. blobs.py.

Reading path#

  1. manifest.py for the vocabulary.

  2. blobs.py, then install.py for what hmp example add does.

  3. generate.py for how the catalog is built from a checkout.

  4. cli/_workers/example.py and cli/commands/example/ for the verb.
