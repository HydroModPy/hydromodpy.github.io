Package: project#

The public face of HydroModPy. api.py holds the fifteen verbs that hydromodpy and hmp expose: open, run, check, calibrate, spinup, replay, stop, status, trash, compare, show, export, publish, example and doctor. A verb takes text, numbers, paths and mappings and gives back a value with to_dict, a path or diagnostics, so a server sends what it gets. A reference is a path, a name read in workspace, or the object itself, and nothing is looked for above the working directory. kept_readers.py keeps read, index and Catalog at the top level beside the verbs.

Project is one object that holds a validated configuration, builds the model once and runs it as often as asked. It is no execution engine, because it calls the workflow layer, so the interactive route and the TOML route share the same steps. launch/ runs a [sites] project as one process per case, exchange/ publishes, installs and replays a copy of a run, dispatch/ binds a workflow name to the call that runs it, and examples/ serves hmp example. lab.py holds Lab, which plays the steps of a run one by one in memory so a model can be built, looked at and changed from Python.

It sits above the layer matrix and reads every layer below it. Only the package root, cli and hydromodpy_server read it. One global crosses to a lower layer, the trial pipeline of calibration/runners/trial.py, which fill_trial_pipeline fills here.

The page of the package in the developer docs lists the modules and tells how the folders fit together and where to add what.

Inside the package#

The fifteen verbs of api.py are the whole public surface. Each verb resolves its source or its reference, calls the function of the package that does the work and returns a typed value. The Python reference of the docs is built from their docstrings. show reads one line of show.SHOWN, so a new value of what is a line of that table.

The trial pipeline is the one global that crosses to a lower layer. Calibration cannot import workflow or project, so it defines the TrialPipeline protocol and trial_pipeline.py implements it. Each entry that reads the pipeline fills it first, which is why the command line fills nothing. No other adapter is wired through a global.

dispatch/ holds the adapters that need the public Project and that lower layers must not import. dispatch/workflow.py binds a workflow name to the call that runs it for hmp run, and rerun.py reruns a recorded run for hmp catalog rerun. They are the one place in project that imports Project outside TYPE_CHECKING, and only inside functions. launch/ and exchange/ never import it. exchange/ carries a run between workspaces (share.py to publish, install.py to install, replay.py to replay), so it needs to see both the run and the data of a workspace.

The launcher of a [sites] project plans many cases once, prepares them once, solves them as separate processes and collects them into summary/. The plan is written once under plan/<hash>/, and it is the same plan for local.py and for SLURM (slurm.py). So a rule that picks cases or sets a worker flag lives in selection.py only, and the two launchers agree. prepare.py fetches the data of every case before any solve. status.py reads the disk and never the index, and summary.py regenerates summary/ from the run directories.

Where to add what#

A new verb is a function of api.py, and the command line calls it (see Add a CLI command). A workflow name is a run_* function and an entry of DISPATCH in dispatch/workflow.py, with the name in KNOWN_WORKFLOWS of workflow/dispatch.py. A kind of file that a published run carries goes to exchange/share.py, a check when installing to exchange/install.py and a check before a replay to exchange/replay.py. In the launcher, a table format or a binding rule of the plan goes to plan.py, a variable of a case environment to env.py, a state that a case can be in to status.py and a column of by_case or by_site to summary_tables.py. A command that a SLURM script calls is a function of slurm.py, a branch of its main and a line of the template, and the module path stays. A folder NN_name of examples/projects/ with a project.toml and a README.md enters the example catalog at the next python -m tools.dev examples manifest, with no line of code.
