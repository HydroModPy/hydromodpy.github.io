Step 5: every export#

Task

Write the results of step 4 in every format HydroModPy can export, and ask for more files once the run exists.

Time

1 to 2 min for the run, 1.5 to 3 min for the command.

Needs

The example files (The staircase). Nothing is downloaded.

Gives

Eight figures and fourteen files, from GeoPackage to a portable archive of the run.

Step 5 does not change the model. It is step 4 with its results written out in every format HydroModPy can export. The file drops the inherited exports with export__delete = true and states its own list, one [[export]] block per request. A block says what (variables), when (time or period), and where and how (format, file, crs).

The map is the field of one of the exports below, watertable_depth_2002-10-15.tif, drawn.

Run it#

hmp run step5_export.toml
hmp export nancon_step5_export --list

--list prints what the run can export, by kind, and writes nothing.

import hydromodpy as hmp

run = hmp.run("step5_export.toml")

Once the run exists, hmp.export(run, ["head", "watertable_depth"], time="2002-10-15") writes more files and returns their paths.

What you get#

Eleven export blocks write fourteen files, in share/nancon_step5_export/. The format follows the data unless the block says otherwise: a vector layer is a GeoPackage, a series or a table is a CSV, and a field at one instant is a GeoTIFF.

The Shapefile is one block and several files (.shp, .dbf, .prj, .shx, .cpg), which the run counts as one export.

Eight figures, drawn from the same data: watershed_id_card, flux_timeseries, hydrograph_sim_obs, watertable_depth_map, seepage_map, seepage_network_confusion_map, downslope_distance_map and flow_persistence_map.

Once a run exists you can also ask for files without editing the TOML, for example hmp export nancon_step5_export head watertable_depth --time 2002-10-15.

Key fields#

[[export]]
variables = "head"What to export: a name, a list of names, or "all" for everything the run holds. required example value
Path
export.variables
More

One namespace covers the mesh fields (head, watertable_depth, seepage_mask...), the series (discharge, discharge_obs...), the vector layers (watershed, hydrographic_network_reference...), the raster layers (watershed_dem...) and the table budget; 'hmp export <run> --list' prints what a run holds. A name no run can hold is refused before the solve.

Accepted
string or list of string
Example
"head", ["head", "discharge"], "all"
# time = ‹string or integer or list of string or integer›The instants to write: a date "YYYY-MM-DD", "first", "last", or a list of them.
Path
export.time
More

A date takes the stress period that holds it. A format that holds one instant (GeoTIFF, Shapefile, GeoPackage, VTU) writes one file per date. Left out, the whole simulation is written. Cannot be given with period.

Accepted
string or integer or list of string or integer
# format = ‹"netcdf" | "geotiff" | "csv" | "geopackage" | "shapefile" | "vtu" | "package" | "stac" | "rocrate" | "prov"›The file format.
Path
export.format
More

Left out, each data takes its natural format, or the one the extension of 'file' names. 'package' writes the portable .hmp archive of the run; 'stac', 'rocrate' and 'prov' write its metadata. Those four describe the whole run and take variables = "all" only.

Values
  • "netcdf" : A NetCDF file (.nc): fields and series over time.
  • "geotiff" : A GeoTIFF raster (.tif), one file per date.
  • "csv" : A CSV table (.csv): series and tables.
  • "geopackage" : A GeoPackage vector file (.gpkg), one file per date.
  • "shapefile" : An ESRI Shapefile (.shp), one file per date.
  • "vtu" : A VTK unstructured grid (.vtu) of the mesh, one file per date.
  • "package" : The portable .hmp archive of the run.
  • "stac" : The STAC metadata of the run.
  • "rocrate" : The RO-Crate metadata of the run.
  • "prov" : The PROV provenance record of the run.
Accepted
"netcdf" | "geotiff" | "csv" | "geopackage" | "shapefile" | "vtu" | "package" | "stac" | "rocrate" | "prov"
# file = ‹path›One exact file to write; its extension gives the format.
Path
export.file
More

A relative file is read from 'folder'. Only for a request that writes one file: several files need 'folder' and automatic names.

Accepted
path
[[export]]
variables = "head"
# time = <string or integer or list of string or integer>
# format = <"netcdf" | "geotiff" | "csv" | "geopackage" | "shapefile" | "vtu" | "package" | "stac" | "rocrate" | "prov">
# file = <path>

Lines generated from the models, as in the reference. Open one for its card.

The other keys of a block are export.period, export.crs and export.folder.
